# 06 — Референсы

Что взято из ODS, Hermes Agent и AIRI. И что нет.

Пять источников изучено, но влияние каждого — в конкретных решениях,
а не в коде. Писать агентный рантайм с нуля было нужно в любом случае.

---

## Сводка

| Проект | Лицензия | Что полезнее всего |
|---|---|---|
| ODS | Apache-2.0, Pixel — ODS-only | модель-менеджер, установка, идеи по безопасности |
| Hermes Agent | **MIT** | агентный рантайм, модульное состояние, навыки, антивирус |
| AIRI | **MIT** | голос, управление ПК, протокол approvals, аудит |
| AirLLM | Apache-2.0 | ничего, отклонён |
| CopilotKit | — | генеративный UI, идея |

Hermes и AIRI — MIT, можно копировать. ODS под Apache-2.0, копируется
с атрибуцией. ODS `vendor/pixel` — грант ODS-only, **копировать нельзя**,
именно поэтому агентный рантайм пишется свой.

## ODS — Osmantic Deployment System

Референс для модели-менеджера и инженерных идей.

### Что взято

| Идея | Что даёт |
|---|---|
| Каталог моделей | `model-library.json` + селектор по профилю. Структура нашего `capabilities.json` и каталога |
| Bootstrap-режим | Маленькая модель сразу, большая грузится в фоне |
| Транзакционная смена модели | Новый runtime проверяется, при провале откат на прошлый |
| Компакция памяти | Потолок удерживаемого хвоста, резерв под вывод |
| Отмена исполнения | Маркер запуска + убийство process group, статус 130 |
| Карантин артефактов | Изоляция загрузок, проверка по digest перед публикацией |
| Идентичность файлов | Привязка к точному хэшу, fail closed при расхождении |
| Уровни автономности | Идея, переосмысленная в трёх режимах разрешений |
| Lean tool surface | `tool_search` / `tool_describe` / `tool_call` |

### Что не взято

| Что | Почему |
|---|---|
| Portal / Pixel | **Лицензия.** ODS-only grant, standalone исключён |
| Стек в Docker и WSL2 | Убран сознательно: +2–4 ГБ RAM, перезагрузка, нет доступа к COM/UIA |
| Qdrant | Заменён sqlite-vec — без отдельного сервера |
| n8n | Заменён собственным тревожным таймером |
| ComfyUI, Langfuse, Perplexica | Не задачи секретаря, жрут ресурсы |
| Установщик | Свой: один `.exe`, без WSL2 |

## Hermes Agent — Nous Research

Лучший референс для агентного рантайма. MIT.

### Что взято

| Идея | Что даёт |
|---|---|
| **28 модулей состояния** | Не один файл `state`, а модули: `health`, `repair`, `lockguard`, `lockowners`, `repair`, `rewind`, `portability`, `identity`, `schema` |
| `state_rewind` | Откат состояния к точке. Отличие от отмены: отмена прерывает, rewind возвращает в прошлое |
| `state_health` | Самопроверка целостности состояния, а не «файл существует» |
| `state_lockguard` + `lockowners` | Кто держит блокировку, защита от зависших |
| Тулсеты с проверкой доступа | Закрывает проблему «реестр возможностей»: что доступно и почему нет |
| Формат agentskills.io | Открытый стандарт навыков, не свой |
| FTS5 для поиска по сессиям | Лексический поиск по истории диалогов. Для документов — sqlite-vec |
| Скрипты вызывают инструменты по RPC | Конвейер из пяти шагов сворачивается в один ход без расхода контекста |
| Раздел про антивирус | Defender и Bitdefender флагают unsigned-бинари. У нас будет то же с `llama-server.exe` |
| `hermes doctor` | Паттерн диагностики с проверками |
| Провайдер как дескриптор | Смена провайдера = смена дескриптора, не кода |
| Slash-команды | `/compress`, `/usage`, `/insights` — ручной триггер compaction и аналитика |

### Как решена проблема антивируса

Hermes документирует ложные срабатывания на `uv.exe`:

| Приём | Применение |
|---|---|
| Проверка подлинности через attestation | для llama.cpp |
| Инструкция по добавлению исключения | в диагностику |
| Исключение на папку, не на файл | обновления ломают хэш |
| Явное «это ложное срабатывание» | в сообщении об ошибке |

### Что не взято

| Что | Почему |
|---|---|
| Python как рантайм | Один `.exe` против Python + Node + uv + ripgrep + FFmpeg |
| Терминальный TUI | Наш продукт — десктоп-приложение с голосом |
| `uv.exe` как зависимость | unsigned-бинарь, ложные срабатывания |
| 40+ инструментов | 9B на 8 ГБ VRAM. Нужно 5–8 точных |
| Контейнерные бэкенды | Мы убрали Docker |
| Honcho | Отдельная зависимость. Проще свой профиль в JSON |
| ACP-адаптер | Поддержка чужого протокола, не наша задача |
| Исследовательский трекинг | Про обучение моделей, не про продукт |

## AIRI — Project AIRI

Лучший референс по голосу и управлению компьютером. MIT.

### Что взято

| Идея | Что даёт |
|---|---|
| **`webai-realtime-voice-chat`** | Инкрементальный голосовой пайплайн: VAD → VAD+ASR → +LLM → +TTS. Точный эталон порядка сборки |
| Разделение `desktop_*` и `browser_dom_*` | Разные поверхности исполнения. DOM надёжнее координат и не жжёт VRAM |
| Приоритет исполнения | Сначала детерминированные пути, потом сырые координаты |
| Протокол `approval_required` | Пять шагов, разрешение переиспользуется для текущего запуска |
| `COMPUTER_USE_APPROVAL_MODE` | `actions` / `all` / `never` — режим подтверждений конфигурируемый |
| **deny-list приложений** | Пароли, параметры, **сам агент** |
| **`dry-run` по умолчанию** | Наблюдение без исполнения, пока пользователь не включил |
| `audit.jsonl` | Append-only журнал + `report.json` + скриншоты |
| Режимы исполнения | `dry-run` / `macos-local` / `linux-x11`. Наш: `dry-run` / `windows-local` |
| Мультипровайдерный TTS | Один интерфейс `TTSProvider`, локальный Kokoro плюс облачные |
| `xsai` | Провайдеры как дескрипторы, 30+ бэкендов |
| `demodel` | Ускорение скачивания моделей |
| `unspeech` | Прокси для аудио, LiteLLM-подход |

### Их формулировка, которую стоит помнить

> The value is in orchestration, not in cursor movement by itself.

> Less convincing demos: long videos of coordinate clicking with no
> trace output; browser form-filling done only by screen coordinates
> when DOM tools were available; tasks that cannot explain afterwards
> what the agent observed, executed, or verified.

То же, что мы вывели сами в брейншторме, но сформулировано чётче.
Подтверждение, что приоритеты верны.

### Что не взято

| Что | Почему |
|---|---|
| `computer-use-mcp` целиком | macOS-only: `NSWorkspace`, `CGWindowList`, Quartz `CGEvent`. Windows на UIA и SendInput |
| Vue как фреймворк | Мы на React + Tauri |
| Electron | Tauri: ~250 МБ против ~40 МБ |
| WebGPU-инференс в браузере | «Другой вид веселья». Плюс нет доступа к ПК |
| VRM, Live2D | Цифровой компаньон, не секретарь |
| Minecraft, Factorio, Kerbal | Не наша задача |
| Мобильный клиент | Нет смысла, есть Telegram |
| Caddy, PostgreSQL, Redis, auth | Их серверная часть. У нас нативно |

## AirLLM — отклонён

Идея: держать один слой модели на GPU, остальные подгружать с диска.
671B на 12 ГБ.

**Почему нет:** узкое место — скорость чтения диска, а не VRAM.
27B = 54 ГБ на диске, каждый токен требует прчитать 54 ГБ. На NVMe это
18 секунд на токен. Плюс: нет API-сервера, нет continuous batching,
нет префикс-кэша.

Годно для офлайн-батчей. Как базовый рантайм секретаря — нет.

## Kevin с Хабра — антипаттерн

Проект `dertefter/Kevin`: prompt «если текста мало — пиши Python»,
вытаскивание кода регуляркой, запись в `execute.py`, `importlib.reload()`,
вызов `answer()`. ChatGPT получил полный доступ к ПК.

Автор сам пишет: «однозначно НЕ безопасно».

| Kevin | Наш проект |
|---|---|
| Модель пишет произвольный Python | Модель вызывает типизированные инструменты |
| `exec()` на месте | Инструменты — API с валидацией аргументов |
| Код в venv, ограниченный перечень модулей | Явные границы: пути, процессы, сеть |
| Неверный код = неверное действие | Неверный аргумент = отказ до исполнения |

**Вывод, который стоит помнить:** Kevin работает на ~100 строках
и делает ровно то, что нужно. MVP должен быть таким же маленьким.
Не 14 этапов, а сначала цикл «спросил → сделал → показал результат».

## Итог

Пять источников. Влияние каждого — в конкретных решениях.

**Писать агентный рантайм с нуля было нужно в любом случае** —
лицензия ODS Pixel исключает копирование, а Hermes и AIRI решают
другой продукт (TUI с Python, VTuber-компаньон на Vue).

Но референсы сэкономили дни работы: декомпозиция состояния, формат
навыков, протокол approvals, deny-list, dry-run, голосовой пайплайн,
браузерный DOM.

**Материала достаточно. Пора писать код.**
