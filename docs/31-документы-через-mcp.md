# 31. Документы через MCP: спека

Составлена 11 ноября 2026 по итогам проверки S10 на живой машине.
Короткий вердикт: **внешний путь работает, своя реализация docx не нужна.**

Документ отвечает на три вопроса: что именно проверено, как это
встраивается в наш рантайм и что осталось непроверенным.

## Что проверено

Проверка шла на Windows x64, без установки приложений: распакован
portable-zip, запущен `*-cli.exe mcp` со stdin/stdout. Ни окна, ни
аккаунта, ни сети.

| PdfCraft 0.20.0 portable | 120 804 409 Б, SHA-256 совпал |
| `wordcraft-cli.exe` | 94.7 МБ, лежит рядом с приложением |
| `pdfcraft-cli.exe` | 97.5 МБ, лежит рядом с приложением |

Команды, которыми это проверялось:

```
wordcraft-cli mcp --automation-read-root DIR --automation-write-root DIR
pdfcraft-cli  mcp --root DIR
pdfcraft-cli  mcp --automation-read-root DIR          # только чтение
```

Отдельно проверено, что при одном read-root запись не просто
не рекомендуется, а запрещена: «write authority is absent».

### xlsx и pptx: тоже работают, но по-разному

| Что | GridCraft 0.18.0 | DeckCraft 0.17.0 |
|---|---|---|
| Архив | 51 755 358 Б, SHA-256 сошёлся | 104 292 946 Б, сошёлся |
| `*-cli.exe` | **20.8 МБ** | 94.1 МБ |
| Подпись | Valid, Learning Machines Inc | Valid |
| Рукопожатие | 9–10 мс | 34–246 мс |
| Инструментов | 22 | 25 |
| Чтение | книга 7 755 Б, значения ячеек точные | презентация 23 620 Б, 3 слайда |
| Текст для RAG | `cat`, `convert` в csv/json/html/pdf | `convert` в md — outline |
| Ограничение папок | **нет флага, открывает любой путь** | есть, чужой путь отклонён |

Последняя строка — не мелочь. DeckCraft, WordCraft и PdfCraft получают
`--automation-read-root`/`--automation-write-root` и сами отказывают
пути вне корня. У GridCraft такого флага нет: `mcp` отвечает «unknown
option», а `open_workbook` спокойно открыл книгу из соседней папки и
прочитал из неё данные.

Значит для GridCraft ограничение папок **нельзя делегировать CLI**.
Правило для него отдельное: файл открывается нами через `--in` при
запуске, модели показываются только `inspect_workbook`, `read_range`
и `get_cell`, а `open_workbook`, `save_workbook` и `execute_command`
не показываются вовсе. Тогда у модели нет аргумента-пути, которым
можно выйти за границу.

## Что берём

| CLI | Зачем | Что умеет |
|---|---|---|
| **WordCraft** | основной | docx, doc, pdf, odt, rtf, html, md, txt, tex; чтение, правка, создание |
| **PdfCraft** | второй | текст, OCR, страницы, склейка/разделение, формы, редакция |
| **GridCraft** | таблицы | xlsx, csv, tsv, json, html, pdf; ячейки, формулы, конвертация |
| **DeckCraft** | презентации | pptx, .deckcraft; слайды, фигуры, текст, outline в md |

Порядок именно такой. WordCraft закрывает наш настоящий пробел — docx —
и отдаёт всего 18 схем, которые помещаются в бюджет контекста целиком.
PdfCraft нужен для сканов и постраничной работы, но его 200 инструментов
нельзя показывать модели списком: только `--compact` (ядро плюс
`tool_search`/`tool_call`). GridCraft и DeckCraft добавляют два формата,
которые `docs.office` уже обещает.

Четыре CLI закрывают все четыре обещанных формата. Ставить их все сразу
не нужно: GridCraft весит 20.8 МБ и может ехать в установщике, а
остальные три — по требованию.

## Что не берём

- Крейты и вендоринг: не опубликованы, тянуть воркспейс дороже своей
  реализации.
- Копирование кода: правило проекта — брать паттерны, не код.
- Бинарники в установщик целиком: 286 МБ на три CLI при нашем NSIS
  в 14 МБ. Исключение — GridCraft, см. «Поставка».
- 200 схем в промпт: это съест контекст раньше, чем начнётся работа.

## Архитектура

Новый модуль `src-tauri/src/documents/`:

```
documents/
  mod.rs      # инструменты для модели: docs.read, docs.info, docs.write
  mcp.rs      # клиент JSON-RPC поверх stdio: spawn, initialize, call
  install.rs  # поиск, проверка и загрузка CLI
```

Клиент — не библиотека MCP, а тонкая обёртка: `initialize`,
`notifications/initialized`, `tools/list`, `tools/call`. Этого
достаточно, и это можно проверить тестом без модели.

Поток одного вызова:

```
модель → docs.read(path)
  → проверка разрешений (files.read) и папки (settings.paths)
  → mcp.call("doc_open", {path}), mcp.call("text_extract")
  → ToolOutput::read(text, summary)
```

Процесс поднимается на один вызов: рукопожатие, работа, остановка.
Это осознанно проще, чем «живёт до конца прогона»: нет общего
состояния между профилями, нет осиротевшего CLI после выхода и нет
вопроса, к какому аккаунту относится процесс. Цена — рукопожатие
каждый раз: 10 мс у WordCraft, до 250 мс у DeckCraft. На фоне разбора
документа это не та величина, ради которой стоит держать чужой
процесс. Если замеры на больших корпусах скажут иное, решение можно
пересмотреть: шов `Mcp` это позволяет.

## Что видит модель

Ровно три инструмента плюс один аварийный люк. Не 18 и не 200.

| id | capability | меняет | Куда идёт |
|---|---|---|---|
| `docs.read` | `files.read` | нет | выбор по расширению, см. ниже |
| `docs.info` | `files.read` | нет | `info` / `doc_info` / `inspect_workbook` |
| `docs.write` | `files.write` | **да** | `new_document` + `save_document` |
| `docs.call` | `files.read` | по инструменту | любой инструмент по имени |

Выбор для `docs.read` — по расширению, и он пишется таблицей, а не
угадывается:

| Файл | CLI | Что зовём |
|---|---|---|
| `.docx`, `.doc`, `.odt`, `.rtf`, `.md`, `.txt` | WordCraft | `open_document` + `get_text` |
| `.pdf` | WordCraft или PdfCraft | `text_extract`; PdfCraft — для сканов |
| `.xlsx`, `.csv`, `.tsv` | GridCraft | `read_range`, только чтение |
| `.pptx`, `.deckcraft` | DeckCraft | `convert` в md, затем читаем outline |

Таблица нужна потому, что «прочитай документ» — один инструмент для
модели и четыре разных пути внутри. Без неё модель начнёт пробовать
CLI по очереди.

`docs.call` показывается только при включённом «расширенном» режиме
документов и требует точного имени инструмента: модель не перебирает
200 схем, а ищет нужную через `docs.call("tool_search", …)`.

## Границы

| Граница | Как |
|---|---|
| Чтение | только `settings.paths` — те же папки, что у `fs.read` |
| Запись | отдельная папка; по умолчанию не задана, значит запись запрещена |
| Размер ответа | обрезать на 1 МиБ с пометкой об обрезке |
| Сеть | не передаётся; CLI работает по stdio и портов не открывает |
| Окно | `CREATE_NO_WINDOW`, как у остальных sidecar-процессов |
| Диск | ни модель, ни CLI не получают корень диска |
| GridCraft | файл открывается нами через `--in`; инструменты с аргументом-путём модели не показываются |

Ограничение папок у трёх CLI задаётся аргументами, но мы проверяем
путь и сами, до вызова. Два замка на одну дверь здесь уместны: CLI —
чужая альфа, и его поведение может измениться между версиями.
У GridCraft второго замка нет вовсе, поэтому у него первый обязан быть
строже: путь выбираем мы, а не модель.

## Проверка подлинности

Перед первым запуском: файл на месте, размер совпадает, SHA-256
совпадает с закреплённым, подпись Authenticode валидна и принадлежит
`CN=Learning Machines Inc`. Любое расхождение — отказ с текстом, а не
запуск «на всякий случай».

Это строже, чем мы обходимся с собственными установщиками: они пока
неподписаны. Для чужого бинарника, который читает документы
пользователя, планка выше — и это осознанное решение.

Таблица живёт в `src-tauri/src/documents/install.rs`. Хеш архива
проверяется до распаковки, хеш exe — после неё и у уже установленных
копий. Второй нужен именно для чужих установок: их архив мы не
качали, а версию определить больше нечем.

Хеш архива — от архива, а не от exe: он опубликован GitHub как
`digest` релиза и потому сверяется без доверия к самому файлу.

Обновление версии — отдельная работа, а не «подтянуть latest». Релизы
выходят раз в двое суток, и незакреплённая версия означает, что завтра
у пользователя другой инструмент. Порядок: поднять версию, прогнать
гейты, обновить хеши, только потом выпуск.

## Поставка

Решает размер, и он у четырёх CLI разный. Реализовано в
`src-tauri/src/documents/install.rs`.

1. **Найти установленный** — сначала наш проверенный корень
   `%APPDATA%\ArkHa\docs-cli\<App>\<версия>\`, затем
   `%LOCALAPPDATA%\Programs\ArtCraft\<App>\`,
   `%ProgramFiles%\ArtCraft\<App>\` и старый
   `%ProgramFiles%\<App>\`. Найденный файл сверяется по SHA-256.
2. **Скачать по кнопке** — архив в `%TEMP%`, проверка SHA-256 архива,
   распаковка только exe и лицензий, проверка SHA-256 exe, затем
   атомарное переименование в целевой каталог.
3. **GridCraft — в установщик.** 20.8 МБ при NSIS в 14 МБ: установщик
   вырастет вдвое, но останется разумным, а таблицы — самый частый
   документ после pdf. Это единственный CLI, для которого такой обмен
   имеет смысл.
4. Остальные три в установщик не класть: 286 МБ на WordCraft, PdfCraft
   и DeckCraft.

Если в системе стоит **другая** версия, поиск возвращает не «не
найдено», а ошибку с путём и требуемой версией. Скачивать поверх чужой
установки молча нельзя: человек мог выбрать её сам, а решение
«поставить рядом» должно быть его.

Вместе с бинарником копируются `LICENSE-APACHE`, `LICENSE-MIT`,
`NOTICE` и `ATTRIBUTION.md` из архива: там лицензии шрифтов, а не
только кода.

## Отказы

| Симптом | Поведение |
|---|---|
| CLI не найден | `docs.*` не показываются, в настройках кнопка «Скачать» |
| Хеш или подпись не сошлись | отказ, файл не запускается, текст с причиной |
| Нет рукопожатия за 5 с | отказ инструмента, процесс убит |
| Процесс упал посреди вызова | один перезапуск, затем отказ |
| Путь вне папки | `ToolError::Outside`, без вызова CLI |
| Документ не разобрался | `ToolError::Unreadable` с текстом CLI |
| Ответ больше лимита | обрезка и пометка, не молчаливая потеря |

## Гейты

1. Рукопожатие и `tools/list` без модели, на закреплённой версии.
2. Чтение тестового docx с таблицей: текст, число страниц.
3. Запись docx и чтение его обратно тем же CLI.
4. Отказ на путь вне read-root и отсутствие файла после записи без
   write-root.
5. Убийство процесса при logout: порождённых процессов не осталось.
6. Чтение xlsx: значения ячеек совпадают с эталоном, включая пустые.
7. `.pptx` в md: в outline есть заголовки всех слайдов и текст фигур.
8. GridCraft не получает путь от модели: `open_workbook` отсутствует
   в списке показанных инструментов, а книга открыта через `--in`.

Пятый гейт важнее, чем кажется: осиротевший CLI держит документы
открытыми и переживает выход из приложения. Восьмой — единственная
защита у GridCraft: своего ограничения папок у него нет.

## Что осталось непроверенным

- Сложный docx: колонки, сноски, вложенные таблицы — проверен только
  простой документ.
- Сканированный PDF и качество OCR на русском.
- Большие файлы: время и память на 100+ МБ.
- Формулы и даты в xlsx: прочитаны значения, а не пересчёт формул и не
  форматирование дат; `check` у GridCraft умеет больше, но не проверен.
- Связи, заметки и анимация в pptx: outline собирается, остальное не
  проверялось.
- `.xlsm` с макросами: открываются ли они без предупреждений и не
  выполняется ли код.
- Русский текст в xlsx и pptx: проверены английские файлы, кодировку
  на кириллице надо подтвердить отдельно.

## Что это меняет в плане

S10 закрыт: собственный разбор docx не пишем. Следующая работа —
MCP-клиент и три инструмента, а не парсер Office.

Четыре CLI закрывают четыре формата, которые обещает `docs.office`.
Но `verified: false` в реестре остаётся до первого гейта: проверено
чтение на наших же файлах, а не на документах пользователя. Менять
галочку по результатам собственного смоук-теста — значит повторить
ошибку, из-за которой реестр уже один раз обещал больше, чем умел.

Из четырёх только GridCraft (20.8 МБ) влезает в установщик без
разговоров. Остальные три — по требованию, как CUDA.
