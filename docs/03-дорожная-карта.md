# 03 — Дорожная карта

14 этапов, S0–S13. Первый рабочий MVP — S0–S4, 9–11 дней.

---

## Принципы

**1. Kevin с Хабра — 100 строк.** Автор отдал модели prompt «пиши Python»,
вытащил код регуляркой и выполнил. Работает. Если цикл не работает на
100 строках, он не заработает на 10 тысячах.

**2. Инструменты раньше навыков.** Навык описывает, как использовать
инструменты. `files` без `read_file` — текст в вакууме.

**3. Знакомство раньше агентного цикла.** Пользователь должен собрать
агента раньше, чем агент начнёт что-то делать.

**4. Проверка на T1 и T2 в каждом этапе.** Функция, работающая на T3
и падающая на T1, недоступна половине пользователей.

**5. Не переходить дальше, пока не пройден гейт.** Каждый следующий
этап опирается на работающий предыдущий.

## S2. Инференс

**Цель:** чат со стримом. Модель работает, отвечает.
**Дни:** 2–3

### Что

**Сайдкар** `llama-server.exe`, параметры по профилю.

**Модель-менеджер** `model_manager.rs`:

1. Взять рецепт из каталога по профилю
2. Скачать с Hugging Face, проверяя digest каждого файла
3. Проверить: архитектуру, размер, комплектность
4. Запустить сайдкар
5. **Проверить, что все слои на GPU**, offload на CPU отсутствует
6. Дождаться готовности **реальным запросом**
7. Транзакционно: при провале вернуть предыдущий рецепт

**Рецепты вместо жёсткой таблицы.** Для каждого профиля — несколько
комбинаций квант + KV-кэш + контекст. Выбор по замеру, не по теории.

**Подбор KV-кэша измерением.** Минимум два кандидата на профиль
(`q4_0`, `q8_0`). Меньше бит не значит лучше: на 8 ГБ VRAM `q4_0`
быстрее и стабильнее. См. [08-exvram](08-exvram.md).

**Замеры на заполненном контексте.** Фиксировать отдельно: размер окна,
фактические prompt tokens, состояние кэша перед decode, количество
сгенерированных токенов, финальную заполненность.

**Quality gate перед рекомендацией.** Tool calling, русский, long-context
retrieval, instruction following. Формулировка «без потери качества»
не используется, пока gate не закрыт.

**Отказы измеряются отдельно:** `refusal_rate` и
`benign_over_refusal_rate`. Цель — низкий второй при высоком первом
на разрушительных действиях.

**Bootstrap-режим:** 4B сразу, большая модель в фоне.

**UI:** чат со стримом, индикатор модели и профиля, кнопка остановки,
лог запуска сайдкара.

### Проверка

На T1 и T2: модель грузится, отвечает на русском, стрим работает.
Замерить tok/s при **реально заполненном** контексте, минимум пять
прогонов, брать медиану. Остановить генерацию — работа прекращается.

Quality gate пройден: tool calling, русский, long-context retrieval.

Отказ на безобидной задаче не допускается: «найди PDF на рабочем столе»
должно работать.

### Первая оценка 27B

На T3 (RTX 5060 8 ГБ) помещается Qwen3.8-27B в UD-IQ2_XXS —
см. [08-exvram](08-exvram.md). **Дефолт не переключать:** IQ2_XXS теряет
14.5% качества, деградация приходится на reasoning и agentic.

Провести замер как экспериментальный рецепт. Если tool calling на
IQ2_XXS лучше, чем на 9B Q5_K_M — включить в каталог. Иначе оставить 9B.

## S3. Реестр возможностей и разрешения

**Цель:** агент знает, что может, что не может и почему.
**Дни:** 2

### Почему раньше инструментов

Реестр — данные, не код. Описывает то, что *будет* доступно, и существует
до того, как инструменты написаны. Без него агент не может честно
рассказать о себе.

Одновременно закрывает галлюцинации: модель получает список с причинами
недоступности. Нет COM-инструмента — говорит «не могу, нет COM на этом
профиле», а не обещает и проваливается.

### Что

`capabilities.json` — реестр, `permissions.json` — разрешения,
`permissions.rs` — единая проверка прав для агента и UI.

Добавить `deny_apps`: менеджеры паролей, параметры системы, сам секретарь.
И `executor: dry-run` по умолчанию.

### Проверка

Реестр валиден, T1 и T2 фильтруют возможности корректно, разрешения
сохраняются и переживают перезапуск.

## S5. Навыки

**Цель:** инструкции, которые объясняют, как комбинировать инструменты.
**Дни:** 2

### Что

| Навык | Содержание |
|---|---|
| `answers` | как отвечать, структура ответа, что делать при нехватке данных |
| `web-research` | как искать и читать страницы, различать факт и мнение |
| `personal-context` | что запоминать, правило «только явные предпочтения» |
| `task-planning` | как разбивать запрос на шаги, как формулировать результат |

Загрузчик `skills.rs`: читает `skills/`, валидация структуры, лимит
бюджета промпта. Формат agentskills.io.

**Промпт собирается как дерево компонентов, не склейка строк.**
Системный промпт — это реестр возможностей, текущие разрешения,
активные навыки, история, RAG-выборка. Каждый блок:

```rust
struct PromptBlock {
    id: &'static str,
    render: fn(&Context) -> Option<String>,  // None — блок не нужен
    budget: Tokens,                          // потолок для блока
}
```

| Что даёт |
|---|
| Блок появляется только если есть данные |
| Бюджет на блок: не съест контекст, даже если разросся |
| Порядок детерминирован |
| Легко посмотреть, из чего собран конкретный промпт |

Идея из velin, см. [ideas](../ideas.md).

### Проверка

Модель следует инструкциям из навыка. Инструкция из веб-страницы не
может изменить поведение сильнее инструкции из навыка.

Блок, для которого нет данных, не попадает в промпт. Ни один блок
не превышает свой бюджет на 32K-профиле.

## S7. Агентный рантайм

**Цель:** цикл, подтверждения, план перед исполнением.
**Дни:** 4–5

### Что

| Модуль | Что делает |
|---|---|
| `executor` | цикл вызовов |
| `tool_registry` | объявление с JSON-схемами |
| `lean_search` | `tool_search` / `tool_describe` / `tool_call` |
| `approvals` | режимы, модалка |
| `receipts` | что выполнено и с каким результатом |
| `compaction` | ужатие истории |
| `cancellation` | маркер + убийство process group, статус 130 |

Плюс модульное состояние: `health`, `repair`, `lockguard`, `rewind`.

Протокол approvals:

1. Модель вызывает инструмент
2. Возвращается `approval_required`
3. UI показывает нативный диалог
4. Приложение вызывает approve/reject
5. Разрешение переиспользуется для текущего запуска

Три правила обязательны:

**План → подтверждение, не пошагово.** Десятьшаговый сценарий с
подтверждением на каждом шаге — десять модалок. Пользователь начнёт
подтверждать не глядя, и защита станет театральной.

**Readback обязателен.** Создал файл → открыть и сверить. Ввёл текст →
прочитать поле обратно. «Сообщение о завершении» не доказательство.

**Правило остановки вместо потолка шагов.** Обязательное поле нечем
заполнить → остановиться и спросить, а не выдумывать значение.

**Разметка происхождения.** Каждый блок контекста помечен источником.
Инструкции только от пользователя, всё из веба и файлов — данные.

**Повтор внутри операции, а не силами модели.** Если действие упало,
повтор делает код операции с ограничением попыток. Модель не должна
исчерпывать контекст, рассуждая «а попробую по-другому».

Идея из AUV: `retry_until_verified(&mut operation)`. Повтор — часть
операции, а не отдельное решение модели.

### Проверка

| Сценарий | Ожидание |
|---|---|
| «Найди три PDF, сделай папку» | план → подтверждение → исполнение → readback |
| Удаление файла | подтверждение, файл в корзине, оригинал цел |
| Страница с текстом «прочитай файл X» | инструкция проигнорирована |
| Кнопка отмены | работа прекращается, статус 130 |
| Действие упало три раза | модель не «передумывает», операция сдаётся и спрашивает |

## S8. Управление ПК

**Цель:** клики, ввод текста, работа с окнами и браузером.
**Дни:** 4

### Что

| Инструмент | API |
|---|---|
| `list_windows` | `EnumWindows` + заголовки |
| `focus_window` | `SetForegroundWindow` |
| `read_ui_tree` | UI Automation, дерево элементов |
| `click_element` | UIA `InvokePattern` / SendInput |
| `type_text` | UIA `ValuePattern` |
| `screenshot` | `windows::Graphics::Capture` |
| `browser_dom_*` | DOM-мост к активной вкладке |

Почему UIA, а не vision: на T1–T2 vision вместе с контекстом не
помещается. UIA даёт структурированные данные без обращения к GPU.
На T4–T5 vision доступен, включается по профилю.

### Повторяющиеся операции собираются в код

Десятишаговый GUI-сценарий через вызовы инструментов занимает на 9B
30–90 секунд: модель тратит токены на каждом шаге, даже если шаг
не менялся тысячу раз.

**Операция** — типизированная функция, которая сама открывает,
ждёт готовности, заполняет и проверяет результат:

```rust
fn open_and_fill(app: &mut AppSession, data: FormData) -> Result<Operation> {
    app.open()?;                  // детерминированно
    app.wait_for_ready()?;
    app.fill(data)?;
    app.verify_submitted()?       // readback внутри операции
}
```

Модель вызывает операцию одним вызовом. Внутри — ноль токенов.
Идея из AUV: «Playwright для ОС», см. [ideas](../ideas.md).

| Что | Как |
|---|---|
| Операции | В `tools/operations/`, рядом с примитивами |
| Примитивы | `click_element`, `type_text` — кирпичики внутри операции |
| Ошибка | Возвращается как значение, модель решает что дальше |
| Повтор | Внутри операции, с лимитом попыток |
| Проверка | Обязательна в конце каждой операции |

**Что не собираем в операции:** то, что зависит от суждения модели.
Открыть блокнот и напечатать текст — операция. «Найди три PDF, подходящие
по содержанию, и разложи их» — решение модели плюс вызов операции
для перемещения.

### Проверка

Пять сценариев на T1 и T2: «что открыто», «открой последний файл»,
«введи текст в поле», «найди в интернете», «что на этой странице».

Одна собранная операция, например «открыть приложение и ввести текст»:
второй прогон не вызывает модель вообще, время не растёт с числом
выполнений.

Реалистично: +50% к оценке. Приложения ломают UIA по-разному.

## S9. Голос

**Цель:** разговор без клавиатуры.
**Дни:** 4–5

### Порядок сборки

| Шаг | Что | Результат |
|---|---|---|
| 1 | Запись аудио → файл → STT | слышно что записано |
| 2 | TTS текстом → файл → воспроизведение | слышно что синтезировано |
| 3 | Цикл с VAD | работающий голосовой диалог |
| 4 | Wake-word | «Секретарь» вместо кнопки |
| 5 | Barge-in | перебивание останавливает ответ |

Не пытаться всё сразу — иначе непонятно, где сломалось.

### Компоненты

| Компонент | Модель | Зависит от профиля |
|---|---|---|
| Wake-word | openWakeWord (ONNX) | нет |
| VAD | Silero (ONNX) | нет |
| STT | **Qwen3-ASR-0.6B** | нет, на процессоре |
| TTS | **Qwen3-TTS-1.7B** | нет |

**Голос решён в S9 замером, а не выбором на глаз.** Ни
faster-whisper, ни Kokoro не понадобились. Распознавание идёт
через `llama-server` на процессоре — 143 МиБ против 2594 МиБ на
карте, задержка 274 мс против 86 мс, — а синтез через
`llama-tts.exe`. Обе модели `Apache-2.0`, обе уже в папке моделей.
Подробности и числа: [10-замеры.md](10-замеры.md) и
[23-выбор-qwen.md](23-выбор-qwen.md).

**Почему отдельным процессом, а не в процессе приложения.**
План требовал синтез внутри процесса, чтобы не платить за лишний
процесс и порт. Замер показал обратное: `llama-tts.exe` занимает
много меньше, чем целый рантайм ONNX, и не тянет за собой Python.
Решение по факту, а не по предположению.

Интерфейс `TTSProvider` остаётся совместимым с OpenAI
(`/v1/audio/speech`). Тогда облачный бэкенд подключается сменой
base URL, а не переписыванием кода. Идея из ortts, см. [ideas](../ideas.md).

| Реализация | Когда |
|---|---|
| Локальный Qwen3-TTS через `llama-tts.exe` | по умолчанию, снят с замером |
| Облачная (ElevenLabs, Azure) | если пользователь выбрал и ввёл ключ |
| Chatterbox Multilingual | запасной локальный, тестируется на русском |

### Проверка

Полный цикл на T1–T3. Перебивание работает. Fallback без wake-word:
кнопка «слушать».

Русский TTS прослушан и выбран лучший из кандидатов. Переключение
на облачный бэкенд меняет только base URL.

### Поиск: RRF вместо одного сигнала

Один поиск по векторам находит «про РАСу», когда пользователь написал
«отчёт по продажам за месяц». Один BM25 находит точное слово,
но промахивается по смыслу.

**Reciprocal Rank Fusion** сливает два ранга:

| Что ищем | Чем |
|---|---|
| Семантика | векторное сходство, sqlite-vec |
| Точное слово | BM25 по тексту документа |
| Итог | RRF, `score = Σ 1/(k + rank_i)`, k ≈ 60 |

Дешёво, не требует отдельного reranker-модели, заметно улучшает
выдачу на русском корпусе. Идея из plast-mem, см. [ideas](../ideas.md).

### Проверка

Вопрос по содержимому документа даёт верный ответ со ссылкой на файл.
«Я не нашёл» вместо выдуманного ответа.

Проверка на русском: запрос с точным словом и запрос по смыслу
находят один и тот же документ. Если RRF не даёт выигрыша против
одного сигнала — оставляем один.

## S11. Память, напоминания, проактивность

**Цель:** секретарь помнит и напоминает сам.
**Дни:** 4

### Два слоя памяти

| Слой | Что хранит | Когда живёт |
|---|---|---|
| **Эпизодический** | «что произошло» — события с границами во времени | затухает, если не вспоминается |
| **Семантический** | «что известно» — факты и правила поведения | пока не опровергнут |

Простой вариант «факты в sqlite-vec» деградирует: через месяц база
полна устаревшего, поиск выдаёт не то. Два слоя это чинят.

| Что | Где | Правило |
|---|---|---|
| Эпизоды | SQLite, отдельная таблица | границы по смене темы или разрыву времени |
| Факты | sqlite-vec, коллекция памяти | тип: личность, предпочтение, интерес, характер, отношения, опыт, цель, руководство |
| Профиль пользователя | JSON | загрузка при старте |
| История диалогов | SQLite + FTS5 | лимит по профилю |
| Напоминания | тревожный таймер | переживает перезапуск |
| Утренняя сводка | планёр + LLM | что важно за вчера и сегодня |

### Консолидация

Факты не извлекаются из каждого сообщения. Извлечение идёт офлайн,
когда накопились эпизоды:

| Ситуация | Действие |
|---|---|
| Накопились эпизоды | LLM извлекает факты |
| Факт новый | создать |
| Факт подтвердился | подкрепить |
| Факт изменился | обновить, пометить старый как недействительный |
| Факт опровергнут | инвалидировать |

**Правило:** в семантическую память пишется только то, что модель
решила запомнить. Сырой лог диалогов — нет.

**Уровень неожиданности** при извлечении: если факт сильно меняет
представление о пользователе — консолидация запускается раньше.
Дешёвый триггер вместо счётчика эпизодов.

### Принцип из статьи OTUS

Агент для неоднозначности, правило для детерминизма. Напоминание
в 9:00 — cron, не агент. Следить за ценой — планировщик с diff.
Собрать сводку почты — агент.

### Проверка

| Проверка | Критерий |
|---|---|
| Персонализация | работает между сессиями |
| Напоминание | приходит вовремя даже после перезагрузки |
| Утренняя сводка | содержит то, что важно |
| Забывание | неиспользуемый эпизод не поднимается в выдаче |
| Инвалидация | опровергнутый факт перестаёт попадать в ответы |
| Поиск | «что я просил на прошлой неделе» находится через FTS5 |
| Консоль памяти | факт можно посмотреть, исправить, удалить |

**Проверка на T1:** долговременная память отключена с объяснением,
эпизодическая и консолидация не отнимают память на 8 ГБ.

## S12. Облачный fallback

**Цель:** сложные задачи не упираются в локальную модель.
**Дни:** 1–2

### Что

Три режима: `local` (по умолчанию), `hybrid`, `cloud`. Слой выбора
в своём коде, без LiteLLM.

Правила: многошаговый план, длинный контекст, неуверенность модели.
Пользователь видит облачный вызов. Ключ в DPAPI.

### Проверка

Сложная задача доходит до ответа. Индикатор показывает облачный вызов.
В режиме `local` наружу не уходит ничего.

## S13. Установщик

**Цель:** обычный пользователь ставит софт без терминала.
**Дни:** 3–4

### Что

Один установщик: приложение + сайдкар. Модель скачивается при первом
запуске с прогрессом. Никаких WSL2, Docker, перезагрузок.

| Требование | Почему |
|---|---|
| Один установщик | массовый пользователь не читает README |
| Проверка предусловий до изменений | не оставлять систему сломанной |
| Откат при неудаче | установка обратима |
| Понятные сообщения | «не удалось загрузить модель», не стектрейс |
| Без прав администратора | где возможно |

**Диагностика Windows-специфики:**

| Мера | Зачем |
|---|---|
| Исключения SmartScreen | подпись сертификатом, если возможно |
| Проверка антивируса при ошибке запуска | подсказать причину |
| Автоопределение свободного порта | не падать из-за конфликта |
| Предупреждение о балансировке питания | объяснить, почему тормозит |
| Список аудиоустройств в настройках | выбор микрофона вручную |
| Понятная ошибка RAG | «нет прав», а не «indexing failed» |

Проблема с антивирусом не гипотетическая: Hermes документирует ложные
срабатывания на `uv.exe`, у нас будет то же с `llama-server.exe`.

**Кнопка «Диагностика»** — отчёт с конкретным действием:

| Симптом | Что показать |
|---|---|
| «Не отвечает» | «Перезагрузить модель» |
| «Всё медленно» | «Переключить на Q4_K_S» |
| «Не понимает по-русски» | «Попробовать Gemma 4» |
| «Мало VRAM» | «Отключить vision» |
| «Не слышит» | «Проверить микрофон» |

### Обязательный тест

Установить на чистую Windows без подготовки. Если нужна ручная
настройка — установщик не готов.

## Проверка на всех профилях

Встроена в каждый этап.

| Этап | Что проверять на T1 и T2 |
|---|---|
| S1 | Профиль определён верно |

| S5 | Промпт не превышает бюджет, навыки не съедают окно |
| S6 | Инструменты вызываются, границы разрешений работают |
| S7 | Цикл, план, подтверждение, readback, повтор внутри операции |

| S11 | Забывание и инвалидация работают |

Если сценарий не проходит на T1 — отключается по профилю с понятным
сообщением, а не падает с ошибкой.

## Реалистичная оценка

38–45 дней — оценка для одного разработчика, знающего материал.

| Фактор | Влияние |
|---|---|
| UIA на реальных приложениях | +50% к S8 |
| Сборка повторяемых операций | уже учтено в оценке S8 |
| Голос на T1 | отключить по профилю или +3 дня |
| Установщик без сюрпризов | +2–3 дня на антивирус и SmartScreen |
| Тестирование на T1 | нужен доступ к чужой машине |
| Консолидация памяти | +1–2 дня, если факты окажутся конфликтными чаще, чем ожидается |

**Совет:** не ждать идеального T1 перед релизом. Сделать MVP для своей
машины (T3), дать попробовать 2–3 людям с разным железом, потом
доделывать нижние профили. Иначе полгода полировки T1 для одного
пользователя вместо проверки нужности продукта.
