# Проверка изоляции и legacy-миграции

Статус на 2026-11-06. `v1.2.2` опубликован. Этот checklist фиксирует оставшиеся ручные и интеграционные проверки; legacy-файлы пользователя не переносить из тестов или агента без явного выбора в приложении.

## Уже реализовано

- [x] Legacy Migration Gate показывает найденные категории и позволяет перенести выбранные данные либо продолжить без импорта.
- [x] Отказ записывается в профиль и оставляет исходные legacy-файлы нетронутыми.
- [x] Импорт использует SQLite online backup, не перезаписывает существующие файлы профиля и исправляет пути импортированных вложений.
- [x] После первого импорта legacy-набор закрепляется за одной установкой/одним аккаунтом, чтобы другие аккаунты не импортировали ту же личную историю.
- [x] Модели и runtime остаются общими и не попадают в legacy-миграцию.
- [x] Папки гостя и аккаунтов разделены. При logout гостя код пытается удалить его каталог.
- [x] Локальные аккаунты перечислены на экране входа; удаление требует пароль удаляемого аккаунта и удаляет только его приватную папку.
- [x] File/RAG/voice guards блокируют доступ к другим профилям и глобальным auth/legacy-файлам, даже при разрешении на весь диск.
- [x] Миграционные unit-тесты покрывают состав preview, SQLite backup, перепривязку вложений и единственное назначение legacy-набора.

## Обнаруженные legacy-данные и границы миграции

В `%APPDATA%\ArkHa` обнаружены старые базы и настройки: `data/secretary.db`, `memory.db`, `permissions.json`, `profile.json`, `audio.json`, `theme.json`, `context`. Модели остаются общими и не переносятся. В проверенном каталоге отдельных папок `attachments` и пользовательских `skills` не обнаружено; код поддерживает их импорт, если они есть на другой установке.

В текущем приложении не найдено отдельного постоянного хранилища чатов или проектов; импортируются память/RAG и связанные вложения из `memory.db`.
