# 07 — Скиллы

Два разных смысла слова. Путать их — источник ошибок.

| Смысл | Что это | Кому | В сборке |
|---|---|---|---|
| Навыки разработки | помогают писать код проекта | разработчику | никогда |
| Навыки продукта | зашиты в секретаря | пользователю | да |

## Часть 2. Навыки продукта

Это то, что зашивается в секретаря. Формат — **agentskills.io**,
открытый стандарт. Не свой.

### Правила

**1. Навык не может расширять набор инструментов.** Он объясняет, как
использовать то, что уже разрешено. Иначе пользовательский markdown
становится вектором повышения привилегий.

**2. Перед загрузкой — аудит.** Проверка на попытки изменить разрешения,
отключить подтверждения, обратиться к сети напрямую.

**3. Навыки грузятся по требованию.** В системный промпт попадает список
доступных плюс один-два активных. На T1 с контекстом 16K навыки
съедают окно.

### Уровень 1: базовые

Работают всегда, на всех профилях. Идут после инструментов: навык
описывает, как их комбинировать.

| Навык | Что описывает |
|---|---|
| `answers` | как отвечать, структура ответа, что делать при нехватке данных |
| `files` | как искать, читать, создавать, переименовывать. Правила подтверждения |
| `apps` | запуск, закрытие, переключение между приложениями |
| `windows` | работа с окнами: список, активация, элементы интерфейса |
| `web-research` | поиск, чтение страниц, проверка источников. Факт против мнения |

### Уровень 2: с памятью

Требуют долговременной памяти. T2+.

| Навык | Что описывает |
|---|---|
| `personal-context` | что запоминать, что нельзя. Только явные предпочтения, не сырой лог |
| `reminders` | как ставить, отменять, как не спамить |
| `morning-brief` | утренняя сводка: что важно за вчера и сегодня |

### Уровень 3: с документами

Требуют RAG. T2+.

| Навык | Что описывает |
|---|---|
| `documents` | как искать по корпусу, как цитировать, что делать если не нашёл |
| `reports` | структура отчёта, источники, что отмечать как неизвестное |
| `summarize` | как суммировать длинные документы без потери ключевого |

### Уровень 4: проактивные

Требуют планировщика. T3+.

| Навык | Что описывает |
|---|---|
| `monitoring` | как следить за источником, как отличить значимое от шума |
| `promises` | как отслеживать обещания пользователя и напоминать о просроченных |

### Уровень 5: пользовательские

Пишет пользователь через UI. Без программирования.

| Пример | Содержание |
|---|---|
| `my-email-style` | «Я отвечаю кратко, без приветствий, подпись в конце» |
| `my-files` | «Документы лежат в D:\Работа, архив в D:\Архив» |
| `my-priorities` | «Приоритет — клиенты, потом документация, потом свои» |

Это то, что делает секретаря персональным. Не настройки, а инструкции.

Генерация: «расскажи секретарю, как ты работаешь» — он сам создаёт навык.
Проходит ту же валидацию.

## Что не зашиваем

| Не зашивать | Почему |
|---|---|
| Финансы, юридические выводы | цена ошибки несоизмерима |
| Установка ПО, системные настройки | необратимо, ломает систему |
| Работа с паролями и ключами | наружу утекает, внутрь приходит инъекция |
| Автоотправка писем | необратимый внешний эффект |
| Удаление файлов без корзины | необратимо |
| Навыки из интернета без аудита | вектор повышения привилегий |

## Подсистема навыков

```
skills/
  files/SKILL.md
  web-research/SKILL.md
  answers/SKILL.md
  ...
```

| Компонент | Что делает |
|---|---|
| Загрузчик | читает `skills/`, валидация структуры |
| Валидатор | формат, размер бюджета промпта |
| Аудит | статический анализ на опасные конструкции |
| Реестр | какие навыки активны, кто автор, когда изменён |
| Инъектор | подставляет навыки по профилю |

**Влияние на контекст:** каждый активный навык стоит токенов. На T1
с контекстом 16K навыки будут мешать. Правило: список доступных плюс
один-два активных, остальное через `tool_describe`.

То же, что lean tool surface, но на уровне инструкций.
