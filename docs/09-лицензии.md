### Голос: распознавание и синтез

Заменяет faster-whisper и Kokoro: приняты Qwen3-ASR и Qwen3-TTS,
обе через тот же `llama-server` и тот же `llama-tts`.

| Часть | Репозиторий | Лицензия | Проверено |
|---|---|---|---|
| Веса распознавания | `Qwen/Qwen3-ASR-0.6B` | `apache-2.0` | 14.10.2026, API Hugging Face, поле `cardData.license` |
| Веса синтеза | `Qwen/Qwen3-TTS-12Hz-1.7B-Base` | `apache-2.0` | 14.10.2026, там же |
| Сборка GGUF распознавания | `ggml-org/Qwen3-ASR-0.6B-GGUF` | **не объявлена** | 14.10.2026, API |
| Сборка GGUF синтеза | `ggml-org/Qwen3-TTS-12Hz-1.7B-Base-GGUF` | **не объявлена** | 14.10.2026, API |

**Что это значит и почему всё равно можно.** GGUF-репозитории поля
`license` не содержат вовсе — это не «запрещённая лицензия», а
отсутствующая метка. Квантование меняет числа в весах, а не права
на них, поэтому лицензия исходных весов распространяется и на
квантованные файлы: `Apache-2.0`. Решение опирается на проверенные
исходные веса, а не на догадку о намерениях автора сборки.

**Что осталось неясным.** Репозиторий, из которого файлы брались
для синтеза, в документации не записан: имена файлов на диске
короче, чем в `ggml-org` (`Qwen3-TTS-1.7B-Q4_K_M.gguf` против
`Qwen3-TTS-12Hz-1.7B-Base-Q4_K_M.gguf`), то есть при загрузке их
переименовали. Размеры совпадают до мегабайта — 988 МиБ и 426 МиБ, —
поэтому источник, скорее всего, именно `ggml-org`. Для
распознавания вопроса нет: имена и размеры совпадают дословно.

Это записано как наблюдение, а не как установленный факт. Лицензия
от этого не меняется: у исходных весов она Apache-2.0 в любом
случае.

### 1. openWakeWord — веса под CC-BY-NC-SA-4.0

| Часть | SPDX | Можно в коммерческом продукте |
|---|---|---|
| Код | `Apache-2.0` | да |
| **Все предобученные модели** | **`CC-BY-NC-SA-4.0`** | **нет** |

Источник: `raw.githubusercontent.com/dscripka/openWakeWord/main/README.md`,
раздел License. Владелец кода — David Scripka.

Модели не лежат в репозитории: они скачиваются из GitHub Releases во
время работы. Значит копирование модели в продукт — это
распространение, и условия CC применяются: атрибуция, ShareAlike на
производные работы и **запрет коммерческого использования**.

Ограничение NC распространяется **на весь набор предобученных моделей**,
а не только на `alexa`. Страница `docs/models/alexa.md` вообще не
содержит утверждения о лицензии — там только архитектура, данные и
метрики.

Влияние: этап S9, шаг 4 «Wake-word». Голос без wake-word работает,
кнопка «слушать» остаётся. То есть продукт не ломается, но обещанное
в плане «Секретарь» вместо кнопки — под вопросом.

**Свою модель обучить можно. NC-ограничение снимается полностью.**

Проверено 11 октября 2026 через API GitHub и по исходникам:

| Компонент | SPDX | Проверено |
|---|---|---|
| Код openWakeWord | `Apache-2.0` | да |
| `piper-sample-generator` (TTS для синтеза) | `MIT` | да |
| `silero-vad` | `MIT` | да |
| `ort`, рантайм ONNX для Rust | `Apache-2.0` | да |

| `target_phrase` в конфиге | задаётся пользователем | да |

Фреймворк явно рассчитан на чужие модели: в конфиге есть
`target_phrase`, `custom_negative_phrases`, шаги `train.py
--generate_clips` и `--augment_clips`. Инференс идёт через ONNX и
принимает **любые** пути к моделям, штатные веса не требуются.

Модель, которую обучили мы, — наша. Ограничение CC-NC висит на
предобученных весах dscripka, которых мы не касаемся.

#### Про выбор набора RIR: зеркало лицензией не годится

Проверено через HF API 11 октября 2026:

```
davidscripka/MIT_environmental_impulse_responses
  license: unknown          ← тег license:unknown на самой карточке
```

Это зеркало, которое openWakeWord тянет **по умолчанию** в
`automatic_model_training.ipynb`. Лицензия на нём не указана.

*На момент решения* правило 15 звучало однозначно: не проверено — не
используем. Правило изменено 12 октября 2026 и больше не запрещает,
но решение ниже остаётся в силе — оно было принято осознанно, а не
по умолчанию.

Значит конвейер в исходном виде запускать нельзя. В
`examples/custom_model.yml` путь задаётся явно:

```yaml
rir_paths:
  - "./mit_rirs"     ← заменить на набор с Zenodo
```

Практический вывод: **обучение не запускаем, пока `rir_paths` не
указывает на CC BY 4.0 источник.** Это не перестраховка: карточка
зеркала сама заявляет `license: unknown`, то есть автор не
гарантировал лицензию ничем.

| Источник | SPDX | Годится |
|---|---|---|
| `davidscripka/MIT_environmental_impulse_responses` | `license: unknown` | нет |
| Zenodo 17180301, Synthetic RIR | `CC-BY-4.0` | да |

### 2. SearXNG — AGPL-3.0-or-later

| Поле | Значение |
|---|---|
| SPDX | `AGPL-3.0-or-later` |
| Владелец | SearXNG project, maintainer Markus Heiser (@return42) |
| Источник | `raw.githubusercontent.com/searxng/searxng/master/LICENSE`, `setup.py` |

Коммерческое использование **разрешено**, но с условиями. Ниже —
что запрещает AGPL на самом деле, по тексту лицензии.

**Решающая формулировка — из статьи 0**, определение convey:

> To "convey" a work means any kind of propagation that enables other
> parties to make or receive copies. **Mere interaction with a user
> through a computer network, with no transfer of a copy, is not
> conveying.**

Наше приложение делает HTTP-запросы к инстансу и не передаёт ему ни
одной копии своего кода. Это прямо разрешено, AGPL на нас не
распространяется.

1. **Статья 13.** Сеть-copyleft: если SearXNG запущен как сетевой сервис,
   удалённым пользователям предлагается исходный код работающей версии.
   Обязательство возникает только при модификации. Немодифицированный
   запуск сетевого сервиса прав не создаёт.
2. **Статья 5(c).** Встранивание в проприетарное приложение требует
   распространить всё произведение под AGPL-3.0-or-later.

Второй пункт — единственный настоящий блокер. Срабатывает он только при
передаче производной работы, то есть при встраивании. Мы этого не
делаем, поэтому обходить ничего не пришлось: решение «не встраивать»
и есть правильное.

Отдельная причина, не лицензионная: SearXNG — Python-приложение.
Вложить его в дистрибутив значит везти Python или контейнер. Обещан
один `.exe`, без Docker и WSL2. Лицензия ломает меньше, чем архитектура.

Влияние: этап S6, инструмент `web.rs`, поиск в интернете. Инструмент
чтения страницы по URL (HTTP-запрос и разбор HTML) лицензией не
затронут — это обычный код.

**Варианты и что в каждом проверено:**

| Путь | Статус |
|---|---|
| Инстанс настраивает пользователь | **Выбрано.** AGPL не применяется: ни передачи кода, ни модификации |
| Встроить SearXNG в дистрибутив | Отказ по §5(c) и по архитектуре |
| Свой поиск по HTTP-эндпоинту поисковика | Лицензия и условия конкретного эндпоинта не проверены |
| Платный API поиска | Условия коммерческого использования не проверены |

**Решение принято 11 октября 2026: адрес инстанса настраивает
пользователь.**

SearXNG не входит в дистрибутив. В настройках есть поле адреса, по
умолчанию пустое, с пояснением что это MetaSearch-инстанс. Пользователь
ставит его сам или указывает свой.

Почему это снимает блокер: ни передачи AGPL-кода, ни модификации —
статьи 5(c) и 13 не применяются.

### Что реально осталось нерешённым

Блокер лицензионный снят полностью. Осталось другое, и это важнее.

**Приватность.** Инстанс получает запросы пользователя. Приемлемо
только для локального инстанса или того, за который пользователь сам
отвечает.

**Удобство — вот где настоящая проблема.** Пустое поле по умолчанию
означает, что у большинства поиск не работает с первого запуска:
возможность есть, а воспользоваться ей нечем. Публичные инстансы
ограничивают автоматические запросы и блокируют ботов, а поднимать
свой обычный человек не станет.

Это продуктовая задача, а не лицензионная. На S6 придётся выбрать:
либо поиск по умолчанию выключен с внятным объяснением, что включать,
либо находится способ, приемлемый для обычного человека без
подготовки.

Инструмент чтения страницы по URL лицензией не затрагивается и
доступен независимо от адреса инстанса.

Открытый вопрос для S6: чем заменить поиск, если пользователь не
поднял инстанс. Читать страницу по URL можно всегда, искать — нет.
Варианты и их лицензии не проверены.

Все четыре проверены через crates.io API, поле `license` в метаданных
последней стабильной версии. Данные получены 11 октября 2026.

| Крейт | Версия | SPDX | Владелец | Ограничения |
|---|---|---|---|---|
| reqwest | 0.13.5 | `MIT OR Apache-2.0` | contributors reqwest | нет |
| tokio | 1.53.2 | `MIT` | Tokio Contributors | нет |
| futures-util | 0.3.34 | `MIT OR Apache-2.0` | futures-rs Contributors | нет |

Источник: `crates.io/api/v1/crates/{reqwest,tokio,futures-util}`,
поле `versions[].license`.

Все три — пермиссивные, без copyleft и без ограничений на коммерческое
использование. В S2 они добавлены ради скачивания моделей и потоковой
передачи ответа.

Замечание по reqwest 0.13: сборка идёт **без** OpenSSL и без системного
хранилища сертификатов, на `rustls`. Это уменьшаетsurface атаки и делает
поведение одинаковым на любой Windows, где корневые сертификаты могут быть
перепутаны с корпоративными.

`sha2` в S2 **не добавлялся**: проверка digest при скачивании модели не
реализована, а заявлять непроверенный код неиспользуемым основанием нет.
Как только появится загрузчик — проверка лицензии и добавление крейта.

### Один квант, разные файлы

| Репозиторий | `Q4_K_M` | SHA-256 |
|---|---|---|
| unsloth | 5 680 522 464 | `03b74727a860a563…` |
| bartowski | 6 169 341 984 | `d784ce9eda1a5a7b…` |
| lmstudio-community | 5 627 044 256 | `cd76ec205963b3b3…` |

Разница почти в гигабайт. Это разные прогоны квантования, и суффикс
`Q4_K_M` не идентифицирует файл. Поэтому рецепт указывает
репозиторий, имя файла и сводку, а проверка идёт по `lfs.oid` из
дерева Hugging Face, а не по имени.

Файл на dev-машине сверен: совпадение с `unsloth/Qwen3.5-9B-GGUF`
побайтовое, по размеру и SHA-256.

## Ссылка на правило

**Правило 15 изменено 12 октября 2026 по решению владельца продукта.**

Было: «не проверена — не используем, неясна — не используем».
Стало: непроверенная лицензия **не блокирует** работу, но
обязательно записывается здесь.

Практические следствия изменения:

| Что | Было | Стало |
|---|---|---|
| `serde_yaml` ради разбора шапки навыка | не брали, лицензия не проверена | можно |
| `tokenizers` для голоса | отложено | можно |
| NSIS и WiX для установщика | отложено | можно |
| BGE-M3 для памяти | отложено | можно |

Решения, принятые **до** изменения, остаются в силе: SearXNG не
встраиваем, чужие веса openWakeWord не используем, зеркало без
лицензии не берём. Это были решения на тот момент, и менять их надо
отдельно, а не задним числом.
