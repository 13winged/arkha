## Решения

### Почему без WSL2 и Docker

Отказ от ODS как рантайма убирает Docker Desktop и WSL2.

| | ODS в WSL2 | Свой нативный процесс |
|---|---|---|
| Установка | PowerShell → WSL2 → Ubuntu → Docker, **перезагрузка** | один `.exe`, без перезагрузки |
| Диск | 40 ГБ минимум | ~15 ГБ |
| RAM в простое | +2–4 ГБ на Docker и WSL2 | 0.4–0.6 ГБ |
| GPU | проброс Docker, лишний слой | прямой доступ |
| Пути Windows | кривые права и пути | нативные |
| COM / UIA | не работают из WSL | работают напрямую |

На 16 ГБ RAM это разница между «впритык» и «свободно».

### Почему Tauri, а не Electron

| Вариант | RAM в простое | Выбор |
|---|---|---|
| **Tauri 2** | ~40 МБ | да |
| Electron | ~250 МБ | нет |
| PySide6 | ~120 МБ | запасной |

Tauri использует системный WebView, без рантайма браузера. На T1 это
120 МБ экономии, которые заметны.

| Слой | Выбор |
|---|---|
| Оболочка | Tauri 2 (Rust) |
| Фронт | React + TypeScript + Vite |
| Состояние | TanStack Query |
| IPC | tauri commands |
| HTTP | `reqwest` |

### Почему llama.cpp сайдкаром, а не библиотекой

| Причина | Что даёт |
|---|---|
| Изоляция | падение инференса не роняет UI |
| Замена | обновляется отдельно от приложения |
| Два экземпляра | основная и быстрая модель для фона |

Параметры:

| Параметр | Значение | Почему |
|---|---|---|
| Контекст | по профилю | 32K на T2, 16K на T1 |
| KV-кэш | подбирается измерением | q4_0 быстрее q8_0 на 8 ГБ, см. [08-exvram](08-exvram.md) |
| Размещение | все слои на GPU | offload на CPU даёт провал скорости в 6–8 раз |
| Tool parser | `qwen3_coder` | без него вызовы не парсятся |
| Thinking | **выкл** | иначе секунды на скрытое рассуждение |

Thinking mode выключается через `chat_template_kwargs.enable_thinking: false`.
Сэмплинг для non-thinking: `temperature=0.7, top_p=0.8, top_k=20, presence_penalty=1.5`.

### Почему два набора инструментов для ПК

Заимствовано из AIRI.

| Набор | Куда | На чём |
|---|---|---|
| `desktop_*` | нативные приложения, окна | UIA, Win32, SendInput |
| `browser_dom_*` | страницы браузера | расширение или WebDriver |
| `browser_agent_run` | целевая веб-задача | делегирование цикла |

Приоритет исполнения: детерминированные пути (`terminal_exec`,
`workflow_*`, `browser_dom_*`) перед сырыми координатами.

На веб-страницах DOM даёт селекторы и значения. Это надёжнее координат
и не жжёт VRAM.

### Почему sqlite-vec, а не отдельный сервер

Векторное хранилище внутри SQLite. Без сервера, без лишней памяти,
без ещё одного процесса, который ломается при установке.

| Что | Хранилище | Почему |
|---|---|---|
| Эмбеддинги документов | sqlite-vec | семантический поиск |
| Долговременные факты | sqlite-vec | семантический поиск |
| История диалогов | SQLite + **FTS5** | лексический поиск |
| Профиль пользователя | JSON | просто |
| Напоминания | SQLite | просто |

FTS5 для своей истории, sqlite-vec для документов — разные задачи,
разные инструменты.

### Почему три состояния разрешений

`auto`, `confirm`, `never` вместо абстрактных L1/L2/L3.

Пользователь не знает, что такое L1. Он знает: «можно удалять или нет».

## Компоненты

### Модель-менеджер

1. Определить профиль
2. Выбрать рецепт из каталога для профиля
3. Скачать с проверкой digest каждого файла
4. Проверить: архитектура, размер, комплектность
5. Запустить сайдкар
6. Проверить, что **все слои на GPU**, offload на CPU отсутствует
7. Дождаться готовности **реальным запросом**, не фактом старта
8. Транзакционно: при провале вернуть предыдущий рецепт

**Bootstrap-режим:** пока большая модель качается, поднимать 4B.
Пользователь начинает работать сразу.

### Рецепты, а не жёсткая таблица

Рецепт — проверенная комбинация кванта, KV-кэша, контекста и флагов
для конкретного ограничения памяти и конкретного железа.

```json
{
  "t2": {
    "llm": "Qwen/Qwen3.5-9B-GGUF",
    "recipes": [
      {
        "name": "Q4_K_M + q4_0",
        "file": "Qwen3.5-9B-Q4_K_M.gguf",
        "kv_cache": "q4_0",
        "context": 32768,
        "full_gpu": true,
        "verified": true,
        "tok_s": 34
      }
    ]
}
```

| Поле | Что даёт |
|---|---|
| `recipes` | несколько комбинаций, лучшая выбирается по профилю |
| `kv_cache` | подбирается измерением, не теоретически |
| `full_gpu` | проверяется при загрузке, нарушение — ошибка |
| `verified` | прошёл ли замер с заполненным контекстом |
| `tok_s` | медиана пяти прогонов, не лучший результат |

**Не верифицированные рецепты не показываются как рекомендация.**

### Правило полного размещения

| Конфигурация | Скорость |
|---|---|
| Частично в VRAM, часть в RAM через PCIe | 3.8–5.5 tok/s |
| Все слои на GPU, offload нет | 31 tok/s |

При частичном размещении каждый токен требует передачи весов через
PCIe, GPU простаивает. **Если модель не помещается — менять квант,
а не оставлять часть в RAM.**

### KV-кэш подбирается измерением

Мы изначально выбрали `q8_0` по всему стеку. Статья ExVRAM утверждает, что
на 8 ГБ VRAM `q4_0` быстрее и стабильнее `q8_0`.

**Замер на S2 этого не подтвердил.** На RTX 5060 8 ГБ с Qwen3.5-9B-Q4_K_M и
промптом в 24 000 токенов разница составила 0.8 процента при разбросе
0.5 — это шум. Подробности в [10-замеры](10-замеры.md).

Формулировка «`q4_0` лучше» отброшена как общая. Осталось то, что верно:
**меньше бит не значит лучше и наоборот.** Зависит от CUDA kernels, Flash
Attention, dequantization path, memory traffic и архитектуры GPU. Выбор
делается замером на конкретной машине, а не переносом вывода статьи.

Для каждого профиля: минимум два кандидата KV, замер, выбор по медиане.

### Проверка размещения: читать лог, а не гадать

Признак полного размещения — строка `offloaded X/Y layers to GPU` при X = Y.

**Строка `CPU_Mapped model buffer size` не означает offload.** Это буфер,
отображённый из файла модели: 545 МиБ из 5669 в нашем замере, при
полностью размещённой модели. Если считать это offload, рабочий рецепт
будет отвергнут и начат бессмысленный поиск меньшего кванта.

Строка появляется только при `-lv 4`. На `-lv 3` её нет, и проверка молча
провалится: размещение окажется «неизвестно». Уровень задан в аргументах
сайдкара и закреплён тестом.

### Методика замеров

Замер только на реально заполненном контексте. Фиксируются отдельно:

| Что фиксировать | Зачем |
|---|---|
| Размер context window | что настроено |
| Фактические prompt tokens | что реально в окне |
| Состояние кэша перед decode | откуда стартуем |
| Количество сгенерированных токенов | объём работы |
| Финальная заполненность | чем закончилось |

«Модель отвечает за 2 секунды» на 300 токенах контекста ничего не значит.
Секретарь работает с длинной историей и RAG-выборкой.

### Quality gate перед рекомендацией

Рецепт попадает в каталог как рекомендуемый только после проверки:

| Что мерить | Зачем |
|---|---|
| Reasoning | многошаговые задачи |
| Instruction following | формат вызовов |
| **Tool calling** | главное для секретаря |
| Long-context retrieval | факт в заполненном контексте |
| **Русский** | целевой язык |
| Factual QA | «не выдумывает» |
| Coding | скрипты по RPC |

Формулировка «без потери качества» не используется, пока gate не закрыт.

### Отказы модели измеряются отдельно

Две разные метрики, смешивать нельзя:

| Метрика | Что показывает |
|---|---|
| `refusal_rate` | сколько раз отказалась на задачах, которые должна была выполнить |
| `benign_over_refusal_rate` | сколько раз отказалась на безобидных задачах |

Цель: низкий `benign_over_refusal_rate` при высоком `refusal_rate`
на разрушительных действиях.

Отказ на безобидной задаче ломает продукт. Поэтому модель оставляется
safety-tuned, а отказы обрабатываются в слое инструментов:

| Действие | Модель | Слой инструментов |
|---|---|---|
| «Найди PDF на рабочем столе» | выполняет | — |
| «Собери файлы в папку» | выполняет | план → подтверждение → исполнение |
| «Удали этот файл» | может отказать | режим `never`, объяснение |
| «Отправь это письмо» | может отказать | L1 всегда с подтверждением |

Uncensored чекпойнт не используется: он смещает границу и для
разрушительных действий тоже.

### Реестр возможностей

Описан в [04-онбординг](04-онбординг.md). Данные, не код: существует
до того, как инструменты написаны.

```json
{
  "id": "files.read",
  "title": "Чтение файлов",
  "tier": "T1",
  "risk": "none",
  "default_enabled": false,
  "needs_grant": "paths"
}
```

Агент получает **читаемый** реестр. Механизм против галлюцинаций:
модель знает, что существует и почему недоступно.

### Хранилище разрешений

```json
{
  "paths": ["C:\\Users\\me\\Desktop"],
  "deny_apps": ["1Password", "KeePass", "Параметры", "Secretary"],
  "capabilities": {
    "files.read":   { "enabled": true,  "mode": "auto" },
    "files.write":  { "enabled": true,  "mode": "confirm" },
    "files.delete": { "enabled": false, "mode": "never" },
    "web.search":   { "enabled": true,  "mode": "auto" }
  },
  "cloud": false,
  "executor": "dry-run",
  "approval_mode": "actions"
}
```

`deny_apps` — приложения, которые агент не может открыть, сфокусировать
или в которые не может ввести текст. Никогда. Секретарь в своём
deny-листе обязателен: агент не должен управлять собственным интерфейсом.

### Agent runtime

| Модуль | Что делает |
|---|---|
| `executor` | цикл: рассуждение → вызов → результат → рассуждение |
| `tool_registry` | объявление инструментов с JSON-схемами |
| `lean_search` | `tool_search` / `tool_describe` / `tool_call` |
| `approvals` | проверка режима, модалка при необходимости |
| `receipts` | запись что выполнено и с каким результатом |
| `compaction` | ужатие истории при приближении к лимиту |
| `cancellation` | маркер запуска + убийство process group, статус 130 |

Состояние разбито на модули, а не один файл. Модульность заимствована
из Hermes: `compression`, `guard`, `health`, `lockguard`, `lockowners`,
`repair`, `rewind`, `portability`, `identity`, `schema`.

`rewind` — откат состояния к точке. Отличие от отмены: отмена прерывает
текущую работу, rewind возвращает систему в прошлое.

### Windows-инструменты

**Примитивы** — кирпичики, из которых собираются операции:

| Задача | Инструмент | Приоритет |
|---|---|---|
| Файлы | `walkdir` + `std::fs` | 1 |
| Запуск приложений | `ShellExecuteW` | 1 |
| Окна | `EnumWindows` | 1 |
| Элементы интерфейса | UI Automation | 1 |
| Клик, ввод | UIA `Invoke` / `ValuePattern` + SendInput | 1 |
| Поиск в интернете | SearXNG | 1 |
| Чтение страницы | HTTP + HTML-парсер | 1 |
| Браузер | browser DOM bridge | 1 |
| Буфер обмена | Win32 clipboard | 2 |
| Уведомления | `toast` / WinRT | 2 |
| Excel, Word | COM | 3 |
| Почта | COM или IMAP | 3 |
| Скриншот | `windows::Graphics::Capture` | 3 |

**Операции** — типизированные функции поверх примитивов:

```rust
fn open_and_fill(app: &mut AppSession, data: FormData) -> Result<Operation> {
    app.open()?;                  // детерминированно
    app.wait_for_ready()?;
    app.fill(data)?;
    app.verify_submitted()?       // readback внутри операции
}
```

Десятишаговый GUI-сценарий через вызовы инструментов занимает на 9B
30–90 секунд: модель тратит токены на каждом шаге, даже если шаг
не менялся тысячу раз. Через операцию — секунда и ноль токенов.

| Свойство | Как |
|---|---|
| Расположение | `tools/operations/`, рядом с примитивами |
| Ошибка | Возвращается как значение, модель решает что дальше |
| Повтор | Внутри операции, с лимитом попыток |
| Проверка | Обязательна в конце каждой операции |

**Что не собираем в операции:** то, что зависит от суждения модели.
Открыть блокнот и напечатать текст — операция. «Найди три PDF, подходящие
по содержанию, и разложи их» — решение модели плюс вызов операции
для перемещения.

Идея из AUV, см. [ideas](../ideas.md).

Правило: инструменты никогда не принимают сырые команды от модели.
Только типизированные аргументы. Это и есть граница безопасности.

### Голос

Пайплайн: `wake-word → VAD → STT → LLM → TTS` с перебиванием.

| Компонент | Модель | Зависит от профиля |
|---|---|---|
| Wake-word | openWakeWord (ONNX) | нет |
| VAD | Silero (ONNX) | нет |
| STT | Qwen3-ASR-0.6B, на процессоре | нет |
| TTS | Qwen3-TTS-1.7B | нет |

**Голос измерен, а не выбран на глаз.** Qwen3-ASR и Qwen3-TTS вместо
faster-whisper и Kokoro, обе через llama.cpp, обе `Apache-2.0`.
Числа и обоснование: [10-замеры.md](10-замеры.md),
[23-выбор-qwen.md](23-выбор-qwen.md).

**Синтез отдельным процессом, не в процессе приложения.** План
требовал обратного; замер показал, что `llama-tts.exe` дешевле
рантайма ONNX и не тянет Python.

Но интерфейс `TTSProvider` совместим с OpenAI (`/v1/audio/speech`).
Тогда облачный бэкенд подключается сменой base URL, а не переписыванием
кода. Идея из ortts.

Кандидаты локального TTS выбираются прослушиванием русского, как
рецепт в модели.

Таблица размеров whisper'а (`tiny`, `base`, `small`) больше не
действует: одна модель на все профили, и она на процессоре.

| Профиль | STT | Цикл |
|---|---|---|
| T1–T5 | `Qwen3-ASR-0.6B-Q8_0` на CPU | 274 мс на фразе |

Модель не зависит от профиля и не занимает видеопамять — 143 МиБ
против 2594 МиБ, если гнать её на карте. Задержка выше, но возврат
2.4 ГиБ того стоит, особенно когда модель агента уже заняла всю
карту.

**Barge-in:** пока TTS говорит, STT слушает. Распознанная речь
останавливает воспроизведение. Проверка эха: сравнение входящего аудио
с синтезированным, иначе агент перебивает сам себя.

TTS за единым интерфейсом `TTSProvider` — локальный Qwen3-TTS плюс облачные
реализации для тех, кому нужно качество.

**Промпт собирается как дерево компонентов, а не склейка строк.**
Системный промпт — это реестр возможностей, текущие разрешения,
активные навыки, история, RAG-выборка. Каждый блок умеет вернуть
`None`, если не нужен, и имеет потолок по токенам.

```rust
struct PromptBlock {
    id: &'static str,
    render: fn(&Context) -> Option<String>,
    budget: Tokens,
}
```

На 32K-профиле переполнение одного блока не вытесняет остальные.
Идея из velin.

### Память и RAG

| Эмбеддинги | Выбор | Почему |
|---|---|---|
| Модель | BGE-M3 (ONNX) | мультиязычный, 8192 ctx, для русского корпуса |

**Два слоя памяти:**

| Слой | Что хранит | Когда живёт |
|---|---|---|
| Эпизодический | «что произошло» — события с границами во времени | затухает, если не вспоминается |
| Семантический | «что известно» — факты и правила поведения | пока не опровергнут |

Простой вариант «факты в sqlite-vec» деградирует: через месяц база
полна устаревшего, поиск выдаёт не то. Два слоя это чинят.

**Консолидация** идёт офлайн, когда накопились эпизоды или факт
оказался неожиданным:

| Ситуация | Действие |
|---|---|
| Факт новый | создать |
| Факт подтвердился | подкрепить |
| Факт изменился | обновить, старый пометить недействительным |
| Факт опровергнут | инвалидировать |

Типы фактов: личность, предпочтение, интерес, характер, отношения,
опыт, цель, руководство.

**Чанкинг по структуре** — заголовкам, не фиксированному размеру.
Обычно 300–800 токенов на чанк с перекрытием по границам разделов.

Индексация — офлайн-процесс. Разбор PDF на каждый запрос нельзя.
Изменение файла переиндексирует только его, через `notify`.

**Бюджет контекста на запрос к документам:**

| Профиль | Top-K | Лимит на чанк |
|---|---|---|
| T1 | 3–5 | 400 токенов |
| T2 | 5–6 | 512 токенов |
| T3+ | 6–8 | 512 токенов |

Больше не поместится вместе с историей — частая причина OOM.

**Поиск двумя сигналами с RRF.** Один векторный поиск находит
«про РАСу», когда пользователь написал «отчёт по продажам за месяц».
Один BM25 находит точное слово, но промахивается по смыслу.

```
score = Σ 1 / (k + rank_i),  k ≈ 60
```

Дешёво, не требует reranker-модели, заметно улучшает выдачу на
русском корпусе. Идея из plast-mem.

**Правило записи в память:** только то, что модель явно решила запомнить.
Предпочтения и факты о работе, не сырой лог диалогов. Иначе качество
поиска деградирует за месяцы.

### Навыки

Формат **agentskills.io** — открытый стандарт, не свой.

| Уровень | Навыки | Профиль |
|---|---|---|
| 1 базовые | `files`, `apps`, `windows`, `web-research`, `answers` | T1+ |
| 2 с памятью | `personal-context`, `reminders`, `morning-brief` | T2+ |
| 3 с документами | `documents`, `reports`, `summarize` | T2+ |
| 4 проактивные | `monitoring`, `promises` | T3+ |
| 5 пользовательские | `my-email-style`, `my-files`, `my-priorities` | T1+ |

**Правило:** навык не может расширять набор инструментов. Он объясняет
как использовать то, что уже разрешено. Иначе пользовательский markdown
становится вектором повышения привилегий.

**Правило контекста:** в системный промпт попадает список доступных
навыков плюс один-два активных. Остальное через `tool_describe` по
требованию. На T1 с 16K навыки съедают окно.

### Облачный fallback

| Режим | Когда |
|---|---|
| `local` (по умолчанию) | только локально, приватность абсолютная |
| `hybrid` | локально по умолчанию, облако на сложное |
| `cloud` | всё в облаче |

Маршрутизация: локально Qwen3.5, облако — на многошаговые задачи,
которые локальная модель тянет плохо. Пользователь видит, когда запрос
ушёл наружу. Ключ в DPAPI, локально.

### Журнал

`audit.jsonl` — append-only, читается без приложения. Плюс `report.json`
и скриншоты после действий.

| Функция | Описание |
|---|---|
| Хронология дня | во сколько открыл файлы, какие страницы смотрел |
| Отчёт по задаче | что сделано, что не получилось |
| Экспорт | в markdown, для отчёта о работе |
| Поиск по истории | FTS5: «что я просил на прошлой неделе» |

Секретарь работает, когда пользователь спит. Без журнала это чёрный ящик.
