## P0-1. CDP-драйвер страницы

**Почему.** Сейчас браузер читается через UI Automation. Это работает, но:
дерево зависит от доступности Chromium, элементы не имеют стабильных DOM-ref,
нет навигации/ожидания загрузки, нет `get_page_text` в том виде, в каком его ждёт модель.
Отсюда циклы «снимок → прокрутка → снимок».

**Что взять.** `browser-toolset/python/cdp_browser.py` — минимальный, но правильный интерфейс:
- запуск Chromium с `--remote-debugging-port=0` и временным профилем;
- чтение `DevToolsActivePort`;
- WebSocket к CDP;
- `Target.createTarget` / `Target.attachToTarget`;
- `Page.navigate` и ожидание `DOMContentLoaded`;
- `read_page` — JavaScript, который назначает `ref_N` заголовкам, ссылкам, кнопкам и полям;
- `left_click` по `ref` (через `scrollIntoView` и `Input.dispatchMouseEvent`) или по координатам;
- `get_page_text` — `document.body.innerText`;
- `wait` и `browser_state`.

Дополнительно из `browser-use` (MIT) взять идеи: индексация интерактивных элементов,
несколько вкладок, `extract_content`, загрузка/скачивание файлов.

**Как на Rust.**
- `tungstenite` (sync) + `url` для WebSocket; `serde_json` уже есть.
- Новый модуль `src-tauri/src/tools/browser_cdp.rs`.
- Инструменты: `browser.cdp_navigate`, `browser.cdp_read_page`, `browser.cdp_click`,
  `browser.cdp_text`, `browser.cdp_wait`, `browser.cdp_state`, позже `tabs`.
- Запуск с отдельным временным профилем; закрывать процесс и удалять профиль по `Drop`.
- UIA-модуль оставить как запасной путь для уже открытого браузера пользователя.
- URL-политика: только `http/https`, запрет `file` по умолчанию; отдельный список доменов.

**Приёмка.**
- Локальная fixture-страница: `read_page` видит поле и кнопку с `ref_N`.
- `cdp_click` по ref меняет заголовок вкладки.
- `cdp_text` возвращает текст статьи.
- Навигация ждёт загрузку, а не фиксированный `sleep`.
- Гейт `browser_cdp_gate` проходит на Chrome и Edge.

**Риски.** Отдельный профиль не содержит логинов пользователя. Это осознанно:
нельзя давать агенту cookie everyday-браузера. Для авторизованных сценариев позже —
подключение к уже запущенному Chrome с `--remote-debugging-port`, только по явному согласию.

## P0-2. Параллельные инструменты и бюджеты

**Почему.** Сейчас вызовы одного хода выполняются последовательно. Модель может вернуть
сразу несколько независимых чтений, и они ждут друг друга. Кроме того, лимит только
по шагам, а не по токенам/стоимости.

**Что взять.** `reference_loop/loop.py`:
- read-only вызовы одного пакета идут параллельно, записи — по одной и в порядке модели;
- `max_batch` — потолок вызовов в одном ходу;
- бюджет токенов на весь запуск, включая субагентов;
- write gate: инструмент с `writes: true` не выполняется без подтверждения;
- verifier: ответ можно отклонить и попросить исправить, но не более одного раза;
- `load_skills` с проверкой дубликатов и выхода за папку.

**Как на Rust.**
- В `agent/executor.rs` разделить вызовы на read-only и side-effecting.
- Read-only пакет выполнять через `std::thread::scope` с ограничением 8 потоков.
- Добавить `Budget { max_turns, max_tokens, max_batch }`; считать usage из ответа модели.
- `verifier` — трейт/колбэк, который получает ответ и сообщения; при отказе — один повтор.
- `write gate` уже есть в виде `Спрашивающий`; оставить его и не обходить.

**Приёмка.**
- Тест с фейковой моделью: два read-only вызова идут параллельно (по времени).
- Пакет из 20 вызовов: 16 выполняются, 4 получают ошибку.
- Превышение бюджета токенов останавливает цикл с внятной причиной.
- Write-инструмент без подтверждения не выполняется.

## P1-1. Хуки и политики инструментов

**Почему.** Подтверждения сейчас есть, но нет программных политик: «запретить запись
в системные папки», «переписать аргумент», «добавить контекст после ошибки».
Это то, что SDK делает через `PreToolUse` / `PostToolUse`.

**Что взять.** `claude-agent-sdk-python/examples/hooks.py`:
- `PreToolUse` → `permissionDecision: allow|deny|ask`, причина, изменённый input;
- `PostToolUse` → дополнительный контекст, предупреждение, `continue: false`;
- `SessionStart` / `UserPromptSubmit` → дополнительный контекст;
- порядок матчеров и остановка цепочки.

**Как на Rust.**
- `agent/hooks.rs`: `enum HookEvent`, `trait Hook`, `HookMatcher`.
- Вызывать до `registry.call` и после; результат хука влиять на `allows`/аргументы.
- Хуки хранить в настройках профиля (JSON), без исполнения произвольного кода.
- Ошибка хука не должна разрешать действие: только запрет.

**Приёмка.**
- Хук блокирует запись в `C:\Windows`.
- Хук переписывает путь в безопасную папку.
- Хук после ошибки добавляет подсказку в результат.
- Тесты на порядок и на «ошибка хука = запрет».

## P1-2. Проверка навыков

**Почему.** Сейчас дубликаты имён молча выигрывает первый, а символическая ссылка
может вывести за папку навыков. `reference_loop` это уже запрещает.

**Что взять.** `load_skills` из `reference_loop` и спецификацию `anthropics/skills`:
- обязательные `name` и `description`;
- имя из шапки, а не из папки;
- запрет двух навыков с одним именем (регистр не важен);
- запрет файла/ссылки за пределами корня навыков;
- прогрессивная выдача: в промпте только имя и описание, полный текст — по вызову.

**Как на Rust.**
- Доработать `skills.rs`: `canonicalize` и проверка `starts_with(root)`.
- При слиянии пользовательских и внешних навыков добавлять `Ошибка` в `сломанные`,
  а не молча пропускать.
- Тесты на дубликат, symlink за корень, отсутствие `description`.

**Приёмка.**
- Два навыка с одним именем → второй в `сломанные`, первый работает.
- Ссылка за корень → навык не загружается, причина видна.
- Существующие навыки без изменений проходят.

## P2-1. SessionStore и resume

**Почему.** Длинная задача может занять больше одного запуска. Сейчас история живёт
в интерфейсе, а агент после перезапуска не помнит, что делал.

**Что взять.** `claude-agent-sdk-python`: `SessionStore`, resume, truncation,
хранение в SQLite/Postgres/Redis/S3 (нам достаточно SQLite).

**Как на Rust.**
- `agent/session_store.rs`: трейт `SessionStore` + SQLite-реализация.
- `agent_chat` принимает `session_id`, сохраняет сообщения и вызовы.
- Компакция уже есть — переиспользовать.

**Приёмка.**
- После перезапуска приложения задача продолжается с того же места.
- Старые сессии можно удалить.
- Тесты на round-trip и на отсутствие чужих сессий.

## P2-2. Снимок экрана и координатные действия

**Почему.** UI Automation не видит canvas, игры, удалённые рабочие столы и
некоторые Electron-приложения. Anthropic `computer-use-demo` решает это снимком
экрана и координатными действиями.

**Что взять.** `computer-toolset` / `computer-use-demo`:
- снимок экрана, масштабирование под модель;
- `left_click`, `right_click`, `double_click`, `scroll`, `type`, `key`;
- ожидание после действия;
- политика: координата приходит только после снимка, а не из головы модели.

**Как на Rust.**
- Windows Graphics Capture или DXGI Desktop Duplication → PNG.
- `screen.capture`, `screen.click`, `screen.scroll` под `windows.control`.
- Сначала пытаться UIA; координаты — только если элемента нет в дереве.
- Обязательное подтверждение и лог координат.

**Приёмка.**
- Снимок окна/экрана сохраняется и отдаётся модели.
- Клик по координате попадает в кнопку на тестовом окне.
- Без снимка координатный клик запрещён.

## P2-3. Песочница для скриптов навыков

**Почему.** Навык может содержать скрипт. Сейчас он исполняется с правами приложения.

**Что взять.** `sandbox-runtime` (Apache-2.0): политика «запрещено всё, кроме
разрешённых путей и доменов», применение на уровне ОС, без контейнера.

**Как на Rust/Windows.**
- Job Object с ограничениями, restricted token, AppContainer, WFP-фильтры.
- Политика в JSON: `read_paths`, `write_paths`, `network_hosts`.
- Запуск только через `skill.run`, не через произвольный shell.
- Это не прямой порт TypeScript: на Windows механизмы другие, нужна своя реализация.

**Приёмка.**
- Скрипт не читает файл вне разрешённой папки.
- Скрипт не ходит в сеть без разрешения.
- Ошибка политики видна человеку.

## P2-4. Yandex Search API v2

Это не модуль для переписывания, а HTTP-служба. SDK на Python не нужен.

- `POST https://searchapi.api.cloud.yandex.net/v2/web/search`
- заголовок `Authorization: Api-Key <key>`
- тело: `query.queryText`, `folderId`, `responseFormat: FORMAT_XML`,
  `query.searchType` (например, `SEARCH_TYPE_COM` / `SEARCH_TYPE_RU`)
- ответ: `rawData` в Base64, внутри XML или HTML
- лимиты: до 250 результатов, запрос до 400 символов

**Как на Rust.**
- `tools/web_yandex.rs`, провайдер выбирается настройкой `web.search.provider`.
- `reqwest` уже есть; для XML добавить `quick-xml`.
- Ключ и `folderId` — только в защищённом хранилище, не в логах.
- Тест на замоканный HTTP; живой тест — при наличии ключа.

## Что не берём

- `anthropics/claude-code` — нет лицензии на репозиторий. Только идеи, без кода.
- `anthropics/anthropic-tools` — нет явной лицензии. Только идеи.
- `Skyvern` — AGPL-3.0. Код не переносим; визуальная навигация — только clean-room
  исследование, если понадобится.
- `maestro` — форк workflow-оркестратора Netflix, к агенту отношения не имеет.
- Playwright целиком — не портируем. CDP-драйвера достаточно, а Rust-биндинги
  Playwright тяжёлые и нестабильные.
- LangChain browser agent — оркестрация дублирует наш executor.

## Порядок работ

1. CDP-драйвер (P0-1) — закрывает текущие циклы и делает браузер предсказуемым.
2. Параллельные инструменты и бюджеты (P0-2) — ускоряет и ограничивает цикл.
3. Хуки (P1-1) и проверка навыков (P1-2).
4. SessionStore (P2-1).
5. Снимок экрана/координаты (P2-2), песочница (P2-3), Yandex (P2-4).

## Лицензии

- MIT: `claude-quickstarts`, `browser-use`, `claude-agent-sdk-python`.
  Порт допустим с сохранением уведомления об авторских правах.
- Apache-2.0: `single-agent-loop-kit`, `sandbox-runtime`, часть `skills`.
  Нужны NOTICE и сохранение уведомлений.
- AGPL-3.0: Skyvern. Только clean-room, без копирования кода.
- Без лицензии: `claude-code`, `anthropic-tools`. Только идеи.

Даже при разрешительной лицензии предпочтителен чистый Rust-код, а не механический
перенос: Python-код опирается на asyncio, Playwright и свои модели данных, которых
у нас нет.
