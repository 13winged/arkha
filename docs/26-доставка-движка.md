# 26. Доставка движка

Решения владельца от 15 октября 2026 и то, как они превращены в
код. Документ отвечает на вопрос «почему установщик весит столько
и почему на машине без видеокарты он меньше».

## Что было сломано

Установленная сборка запускается и рисуется целиком, но модель
не поднимается никогда. Причина: движка нет в установщике.

Приложение ищет `llama-server.exe` рядом с собой
(`model_manager::bin_dir_со`), а в `%LOCALAPPDATA%\ArkHa` после
установки лежат только `arkha.exe` и `uninstall.exe`.

Проверено 15.10.2026: двадцать секунд приложение не мигает, одно
окно, 27 МиБ, CPU 0.1 с. Значит дело не в отрисовке.

Дополнительно: папка `data\bin` в `.gitignore`. Движка не было ни
в репозитории, ни в установщике — механизма доставки не
существовало вовсе.

## Решение 1. CUDA только когда есть карта

**Решение владельца: библиотеки CUDA грузятся только когда на
машине есть видеокарта.**

Обоснование по размерам, посчитано 15.10.2026:

| Что | Размер |
|---|---|
| `llama-server.exe`, `llama-tts.exe` | меньше 0.1 МиБ вместе |
| `cudart64_13.dll` | 0.5 МиБ |
| `cublas64_13.dll` | 52.4 МиБ |
| `cublasLt64_13.dll` | 469.9 МиБ |
| **Итого CUDA** | **523 МиБ** |
| Движок для процессора | **48 МиБ** |

Машина без NVIDIA не получает 523 МиБ, которых она не умеет
использовать. Машина с картой получает их по запросу — там они
нужны.

## Что едет в установщике

Только движок для процессора, из официального релиза
`ggml-org/llama.cpp`:

| Файл релиза | Размер | Куда |
|---|---|---|
| `llama-b11583-bin-win-cpu-x64.zip` | 18.6 МиБ | установщик, 48 МиБ распакованных |

Версия закреплена: `build 11583, commit 988015788`. Проверено
15.10.2026, движок из установочной папки запускается.

Папка кладётся как `bin\llama` рядом с программой — это один из
путей, которые `bin_dir_со` и так проверяет, искать больше ничего
не пришлось.

В установщик едут все библиотеки `ggml-cpu-*.dll`: `llama.dll`
выбирает нужную по микроархитектуре процессора уже во время
работы, и отфильтровать этот набор по названию нельзя.

Лицензия движка едет вместе с файлами: `bin\LICENSE-llama.cpp`,
MIT, текст качается скриптом.

Папка получается скачиванием, поэтому в `.gitignore`. Скрипт:
`scripts/fetch-llama.ps1`. Он сверяет размер скачанного с размером
из списка активов релиза и отказывается работать, если имя файла
в релизе другое: ручное имя файла уже стоило нам двух неверных
скачиваний.

## Решение 2. MCP только локальный

**Решение владельца: по умолчанию работают только локальные
MCP-серверы, подключение чужого — отдельное решение человека с
предупреждением.**

Причина не техническая, а продуктовая. ArkHa обещает: всё
считается на машине человека, облако выключено, телеметрии нет.
MCP-сервер — это чужой код, получающий доступ к инструментам
секретаря. Удалённый сервер отменяет обещание.

Поэтому:

1. Список серверов по умолчанию — локальные: процессы на этой
   машине, запущенные человеком или настроенные им.
2. Подключение чужого сервера — не переключатель в настройках, а
   действие с явным предупреждением о том, что запросы и ответы
   покинут машину.
3. Соединение должно быть видно постоянно, а не только в момент
   подключения: человек должен понимать, куда уходят его данные
   прямо сейчас.

Тот же принцип, что и с голосом: включает человек, само не
поднимается.

## Проверка 15.10.2026: движок в установщике есть

Собраны оба установщика с включёнными ресурсами:

| Установщик | Было | Стало |
|---|---|---|
| NSIS, `ArkHa_0.1.0_x64-setup.exe` | 2.87 МиБ | **12.74 МиБ** |
| MSI, `ArkHa_0.1.0_x64_en-US.msi` | 3.91 МиБ | **23.82 МиБ** |

Рост вчетверо — и вместо программы, которая не может запустить
модель, получается программа, которая может.

Проверено не по манифесту, а распаковкой. MSI административной
установкой распакован во временную папку: 55 файлов, 58 МиБ, и
движок лежит ровно там, где его ищет приложение:

    <папка установки>\bin\llama\llama-server.exe

Рядом `LICENSE-llama.cpp` и все 14 библиотек `ggml-cpu-*.dll`.
Движок из этой папки запущен, отвечает `build 11583,
commit 988015788` — та же версия, что закреплена в замерах.

## Докачивание: сделано и проверено

Модуль `engine.rs`. Человек нажимает кнопку во вкладке «Скачать»,
приложение спрашивает у GitHub состав релиза, качает два архива и
распаковывает их на место. Ничего само не лезет: 550 МиБ — решение.

| Что | Размер в релизе |
|---|---|
| `llama-b11583-bin-win-cuda-13.4-x64.zip` | 146.3 МиБ |
| `cudart-llama-bin-win-cuda-13.4-x64.zip` | 403.9 МиБ |

Живым прогоном 15.10.2026 проверен **только второй** архив — тот,
что весит больше всех и в котором лежат сами библиотеки:

| Что | Ждали по API | Скачали | Что после распаковки |
|---|---|---|---|
| `cudart-llama-bin-win-cuda-13.4-x64.zip` | 423 535 356 | 423 535 356 | 3 файла |

Первый архив не качался: на этой машине библиотеки уже есть, и
повторная загрузка 146 МиБ ради проверки была бы тратой без
здесь. Его размер взят из списка активов релиза, а не измерен
здесь.

Распакованное сверено с тем, что уже лежит в рабочей папке
проекта, — **совпадает побайтно**:

| Файл | Размер | Сверен |
|---|---|---|
| `cudart64_13.dll` | 0.5 МиБ | да |
| `cublas64_13.dll` | 52.4 МиБ | да |
| `cublasLt64_13.dll` | 469.9 МиБ | да |

То есть путь загрузки даёт ровно тот же движок, на котором сняты
все числа в `docs/10`. Это и было целью проверки: если бы скачалось
что-то другое, замеры перестали бы быть переносимыми.

Скорость на этом прогоне: 18.4 МиБ/с, 80 событий о ходе.

### Что учтено при разборе архива

Имя файла из архива используется **только как имя**. Путь не
используется: в zip может быть `../..` и буква диска, а
распаковка идёт в папку установки от имени человека с правами
администратора. На это есть тест.

Сводка сверяется **по размеру**: GitHub не отдаёт `sha256` в API.
Размер — единственное, чем он делится, и он же ломает загрузку,
оборванную на середине. Свою сводку после скачивания приложение не
запоминает, и это осознанный долг: после отмены загрузка
начинается заново.

### Когда библиотеки нужны

Только когда на машине есть NVIDIA. Проверяется имя адаптера, а не
наличие видеопамяти: память есть и у встроенной графики Intel, и у
карт AMD, а нужны библиотеки NVIDIA. Ошибка в эту сторону дорогая,
машина без NVIDIA получила бы 523 МиБ ненужного.

Проверено на этой машине: `NVIDIA GeForce RTX 5060`, `cuda есть:
true`, `cuda нужна: false`.

### Чего панель не делает

Не качает сама и не качает на профилях, где карты нет. На T1 и T2
вопрос не возникает: там по определению нет NVIDIA, и кнопка не
показывается вовсе.

## Что осталось сделать по движку

| Что | Сложность |
|---|---|
| Докачать CUDA по наличию карты | нужна команда загрузки и распаковки zip, вкладка DOWNLOAD уже есть |
| Определять NVIDIA по имени | `Hardware.gpu_name` уже хранит описание адаптера, достаточно проверки на `NVIDIA` |
| Не грузить CUDA на профилях T1 и T2 | там карты нет по определению, проверять нечего |
| Показать в интерфейсе, что движка нет | сейчас сообщение есть, но не на первой странице |

Пока этого нет, машина с NVIDIA после установки увидит движок без
библиотек CUDA и не сможет работать на карте. Профили T1 и T2
работают сразу.

## Чего этот документ не утверждает

Что установленная копия запускает модель — не проверено. Проверено,
что движок лежит в установщике по нужному пути и отвечает. Запуск
модели из установленной папки на живой машине требует, чтобы
человек поставил эту сборку, и это ещё предстоит.
