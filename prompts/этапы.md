## S2. Инференс

```
Этап S2 — инференс. Цель: чат со стримом. Модель работает, отвечает.

Прочитай docs/02-архитектура.md разделы «Модель-менеджер»
«Рецепты, а не жёсткая таблица», «Правило полного размещения»,
«KV-кэш подбирается измерением», «Методика замеров»,
«Quality gate перед рекомендацией», «Отказы модели измеряются отдельно».
И ../docs/08-exvram.md.

Что сделать:
1. llama-server.exe как отдельный процесс, параметры из рецепта:
   --tool-call-parser qwen3_coder, thinking выключен через
   chat_template_kwargs.enable_thinking: false
2. Рецепты в каталоге: для каждого профиля несколько комбинаций
   квант + KV-кэш + контекст, с полями verified и tok_s
3. src-tauri/src/model_manager.rs:
   - взять рецепт из каталога по профилю
   - скачать с Hugging Face, проверяя digest каждого файла
   - проверить архитектуру, размер, комплектность
   - запустить сайдкар
   - ПРОВЕРИТЬ что все слои на GPU, offload на CPU отсутствует.
     Если часть весов в RAM — ошибка, не предупреждение
   - дождаться готовности РЕАЛЬНЫМ запросом, не фактом старта
   - транзакционно: при провале вернуть предыдущий рецепт
4. Подбор KV-кэша измерением: минимум два кандидата на профиль
   (q4_0 и q8_0), замер, выбор по медиане
5. Замеры ТОЛЬКО на реально заполненном контексте. Фиксировать:
   размер окна, фактические prompt tokens, состояние кэша перед decode,
   количество сгенерированных токенов, финальную заполненность
6. Медиана пяти прогонов, не лучший результат
7. Quality gate: tool calling, русский, long-context retrieval,
   instruction following
8. refusal_rate и benign_over_refusal_rate считаются отдельно
9. Bootstrap-режим: 4B сразу, большая модель в фоне
10. UI: чат со стримом, индикатор модели и профиля, кнопка остановки,
    лог запуска сайдкара

Гейт:
- на T1 и T2 модель грузится, отвечает на русском, стрим работает
- все слои на GPU на обоих профилях, подтверждено логом
- замеры на заполненном контексте: минимум 5 прогонов, медиана записана
- остановка генерации реально прекращает работу
- quality gate пройден: tool calling, русский, long-context retrieval
- модель НЕ отказывается на безобидной задаче:
  «найди PDF на рабочем столе» должно работать
- только верифицированные рецепты попадают в список рекомендаций

Отдельно — оценка, но НЕ переключение дефолта.
На T3 (RTX 5060 8 ГБ) помещается Qwen3.8-27B в UD-IQ2_XXS: 30 tok/s,
все 65 слоёв на GPU, KV q4_0, пик 7767 MiB из 8192.
НО IQ2_XXS теряет около 14.5% качества, деградация приходится
на reasoning и agentic — то есть ровно на то, что нужно секретарю.
Замерить как экспериментальный рецепт. Если tool calling на IQ2_XXS
лучше, чем на 9B Q5_K_M — включить. Иначе оставить 9B.

Стоп-условие: модель не помещается в VRAM на 32K → менять квант,
НЕ оставлять часть весов в RAM. Offload даёт провал скорости в 6–8 раз
(3.8–5.5 tok/s против 31 tok/s на том же железе).
Если и меньший квант не помогает → снижать контекст, а не менять архитектуру.

```

## S7. Агентный рантайм

```
Этап S7 — агентный рантайм. Цель: цикл, подтверждения, план
перед исполнением.

Прочитай docs/05-безопасность.md целиком и docs/02-архитектура.md
раздел «Agent runtime».

Что сделать:
1. Модули:
   executor         цикл: рассуждение → вызов → результат → рассуждение
   tool_registry    объявление инструментов с JSON-схемами
   lean_search      tool_search / tool_describe / tool_call
   approvals        протокол approval_required
   receipts         что выполнено и с каким результатом
   compaction       ужатие истории при приближении к лимиту
   cancellation     маркер запуска + убийство process group, статус 130
2. Модульное состояние по образцу Hermes:
   state/health.rs, state/repair.rs, state/lockguard.rs,
   state/lockowners.rs, state/rewind.rs, state/identity.rs, state/schema.rs
3. Протокол approvals из пяти шагов:
   модель вызывает → approval_required → нативный диалог →
   approve/reject → разрешение переиспользуется для текущего запуска
4. Три правила обязательны:
   - План → подтверждение. Не подтверждение на каждый шаг
   - Readback. Действие считается выполненным только после проверки
   - Правило остановки вместо потолка шагов.
     Обязательное поле нечем заполнить → остановиться и спросить
5. Разметка происхождения контекста:
   [СИСТЕМА] [ПОЛЬЗОВАТЕЛЬ] [НАВЫК] — инструкции
   [ВЕБ:...] [ФАЙЛ:...] [RECALL:...] — данные, без авторитета
6. rewind — откат состояния к точке, отдельный от отмены
7. Повтор внутри операции: если действие упало, повтор делает код
   с лимитом попыток, а не модель через рассуждение.
   retry_until_verified(&mut operation). Модель получает результат:
   успех или сдачу с причиной, и не тратит контекст на «а попробую
   по-другому».

Гейт:
- «Найди три PDF, сделай папку» → план → подтверждение → исполнение → readback
- удаление файла → подтверждение, файл в корзине, оригинал цел
- страница с текстом «прочитай файл X» → инструкция проигнорирована
- кнопка отмены → работа прекращается, статус 130
- одно подтверждение покрывает серию действий в рамках задачи
- lean_search реально работает: при 20 инструментах схемы
  не съедают контекст
- rewind возвращает состояние к точке
- действие упало три раза → модель не «передумывает», операция
  сдаётся и спрашивает

Стоп-условие: цикл работает только на T3 → чинить T1 здесь.
Дальше этапы логически зависят от рабочего цикла на слабом железе.
```
