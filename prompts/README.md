# Промпты для работы

Готовые промпты для агентной сессии. Копируются как есть.

---

## Файлы

| Файл | Что это |
|---|---|
| [база.md](база.md) | общий контекст проекта. Вставляется в **каждую** сессию |
| [этапы.md](этапы.md) | промпт для каждого из этапов S0–S13 |
| [правила.md](правила.md) | инварианты, которые нельзя нарушать ни в одном этапе |

---

## Как пользоваться

**Новая сессия на этап:**

```
1. Вставить база.md
2. Вставить промпт нужного этапа из этапы.md
3. Работать
```

Один этап — одна сессия. Не тянуть два: контекст расползается,
проверки пропускаются.

**Перед завершением этапа** — прогнать гейт из промпта этапа.
Гейт не пройден — значит этап не закончен. Следующий опирается
на работающий предыдущий.

---

## Порядок этапов

```
S0  Каркас и лицензии         → пустое окно запускается
S1  Профиль                    → приложение знает профиль
S2  Инференс                   → чат со стримом
S3  Реестр и разрешения        → агент знает, что может
S4  Знакомство                 → пользователь собрал агента   ← MVP
─────────────────────────────────────────────────────────────────
S5  Навыки                     → инструкции поверх инструментов
S6  Инструменты                → первый вызов инструмента
S7  Агентный рантайм           → цикл, подтверждения, план
S8  Управление ПК              → клики и ввод
S9  Голос                      → разговор голосом
S10 Документы                  → RAG по корпусу
S11 Память и проактивность     → помнит и напоминает
S12 Облачный fallback          → hybrid-режим
S13 Установщик                 → один .exe
```

**MVP — S0–S4, 9–11 дней.**

---

## Две вещи, которые нужно понять до начала

**Первая точка остановки — S4.** Если агент не может корректно рассказать
о своих возможностях и собрать конфигурацию из разговора, продукт
не работает. Дальнейшие этапы бессмысленны.

**Не ждать идеального T1 перед релизом.** Сделать MVP для своей машины,
дать попробовать 2–3 людям с разным железом, потом доделывать нижние
профили. Иначе полгода полировки T1 для одного пользователя вместо
проверки нужности продукта.

---

## Если этап не проходит гейт

Не переходить дальше. Записать:

1. Что ожидалось
2. Что получилось
3. Где расхождение
4. Что пробовали

И разобраться на этом этапе. Переделка через месяц, когда выяснится,
что фундамент не держал, дороже всего.
