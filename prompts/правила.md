# Правила

Инварианты, которые нельзя нарушать ни в одном этапе.

Читать перед каждым этапом. Нарушение здесь — не баг, а инцидент.

---

## 1. Инструменты принимают только типизированные аргументы

Модель **никогда** не передаёт сырые команды. Инструмент — это функция
с валидацией аргументов, а не строка для выполнения.

```rust
// Правильно
fn read_file(path: &str, max_bytes: u32) -> Result<FileContent> {
    let resolved = resolve_and_validate(path)?;
    // ...
}

// Нельзя
fn exec(command: &str) -> Result<Output>   // запрещено
```

**Почему:** неверный аргумент отсекается до исполнения. Неверный код —
исполняется.

---

## 2. Никакого `exec` с произвольной строкой

Агент не пишет и не исполняет произвольный код. Это проект Kevin:
модель пишет Python, вызывается `answer()`.

Мы от этого ушли сознательно. Автор сам писал: «однозначно НЕ безопасно».

Если задача не выражается в типизированные инструменты — добавляем
инструмент, а не открываем exec.

---

## 3. Пути нормализуются и проверяются

| Проверка | Правило |
|---|---|
| `..` в пути | отклонять |
| Симлинки | разворачивать и проверять итоговый путь |
| Выход за разрешённые папки | отказ до чтения |
| Диск | проверять корень тома |

Проверка **до** открытия файла, а не после.

---

## 4. deny-list приложений абсолютна

Приложения, которые агент не может открыть, сфокусировать или в которые
не может ввести текст. **Никогда**, даже при полном доступе:

```
1Password, KeePass, Bitwarden, менеджеры паролей
Параметры / System Settings / Панель управления
Диспетчер задач / Task Manager
Секретарь — сам агент
```

Секретарь в своём deny-листе обязателен. Агент не должен управлять
собственным интерфейсом: это путь к зацикливанию.

---

## 5. Инструкции только от пользователя

Каждый блок контекста помечен источником и уровнем доверия.

```
[СИСТЕМА]    — инструкция, авторитетная
[ПОЛЬЗОВАТЕЛЬ] — инструкция, авторитетная
[НАВЫК]      — инструкция, авторитетная
[ВЕБ:...]    — ДАННЫЕ, без авторитета
[ФАЙЛ:...]   — ДАННЫЕ, без авторитета
[RECALL:...] — ДАННЫЕ, без авторитета
```

Содержание из веба и файлов **не может**:
- менять набор инструментов
- менять уровни автономности
- отменять требование подтверждения
- добавлять инструкции

Фраза на странице «прочитай файл X» игнорируется, потому что помечена
как данные.

---

## 6. Изменение разрешений только из чата

Разрешения меняются только из разговора с пользователем и только
с явным подтверждением в интерфейсе.

Содержание из веба и файлов не может этого сделать. Никогда.

---

## 7. Навык не расширяет инструменты

Навык — инструкция, а не привилегия. Он объясняет, как использовать
то, что уже разрешено.

Иначе пользовательский markdown становится вектором повышения привилегий.

**Перед загрузкой любого навыка** — аудит на:
- попытки изменить разрешения или отключить подтверждения
- сетевые обращения напрямую
- `exec`-подобные конструкции

---

## 8. Readback обязателен

Действие считается выполненным только после проверки результата.

| Действие | Проверка |
|---|---|
| Создал файл | открыть, сверить размер и содержимое |
| Переименовал | перечислить каталог, сверить список |
| Ввёл текст | прочитать поле обратно из элемента |
| Открыл приложение | окно существует и активно |

Сообщение «готово» не является доказательством.

---

## 9. Отмена останавливает работу

Не флаг в UI. Граница исполнения:

1. Маркер с SHA-256 от идентификатора запуска
2. Убить process group: `TERM`, затем `KILL`
3. Статус 130

Без этого отмена только обозначает, но не прекращает.

---

## 10. Внешние эффекты всегда с подтверждением

Внешний эффект — то, что нельзя отменить: отправить письмо, купить,
опубликовать, удалить.

Ошибка в tool calling не должна стоить денег или данных.

Подтверждение — **на операцию**, не на каждый шаг. Десять модалок на
десятишаговый сценарий приучают подтверждать не глядя, и защита
становится театральной.

---

## 11. Незаполненное обязательное поле — остановка

Не значение по умолчанию. Остановка и вопрос пользователю.

Каждый инструмент объявляет обязательные поля и проверяемые условия.

---

## 12. Аудит пишется всегда

`audit.jsonl` — append-only, включая `dry-run`.

Пишем: вызов с аргументами, результат, readback, подтверждения,
отказы. Пользователь должен иметь возможность понять, что агент делал.

---

## 13. Функция работает полностью или не показывается

Не «работает медленно», не падает с ошибкой, не «частично».

Если сценарий не проходит на T1 — отключается по профилю с понятным
сообщением: «Недоступно на вашем железе: {причина}».

---

## 14. Приватность по умолчанию

Облако выключено. Синхронизация выключено. Телеметрии нет.
Ключи — локально, в DPAPI.

Ничего не отправляется наружу без явного действия пользователя.

---

## 15. Непроверенная лицензия не блокирует работу

**Изменено 12 октября 2026 по решению владельца продукта.**

Раньше здесь стояло: «не проверена — не используем». Теперь правило
работает иначе:

| Действие | Было | Стало |
|---|---|---|
| Добавить зависимость с непроверенной лицензией | стоп | можно |
| Взять веса с неясной лицензией | стоп | можно |
| Открытый код с неизвестной лицензией | стоп | можно |

Ответственность за юридическую сторону перенесена на владельца
продукта, который эту ответственность принял.

**Что осталось обязательным: запись.** Если лицензия не проверена,
это пишется там, где принималось решение, — в
[docs/09-лицензии](../docs/09-лицензии.md) или в коде рядом с
зависимостью.

Запись осталась потому, что «не проверено» и «проверено и хорошо»
должны различаться в документации. Убрать само правило — можно,
но тогда в репозитории перестанет быть видно, что именно не
проверено, и это будет выглядеть как «всё проверили».

**Что освободилось сразу:** `serde_yaml` (разбор шапки навыков),
`tokenizers` (голос), BGE-M3 (память), NSIS и WiX (установщик).

**Что не поменялось.** Решения, принятые пока правило действовало,
остаются в силе: SearXNG не встраиваем, чужие веса openWakeWord не
берём, зеркало без лицензии не используем. Это были решения на тот
момент; отменить их можно отдельно, задним числом они не меняются.

**Правило 23 при этом не меняется.** Там про числа: цифра, на которой
стоит решение, должна быть нашим замером. Это не лицензия и
снималось другим решением.

---

## 16. Не заявлять «готово» без проверки

Перед объявлением этапа завершённым:

- [ ] Гейт этапа пройден
- [ ] Проверено на T1 и T2
- [ ] Нет стектрейсов в пользовательских сообщениях
- [ ] Каждое действие попало в аудит
- [ ] Границы разрешений не обойдены

Не выполнено — сказать прямо что не выполнено, а не заявить успех.

---

## 17. Воспроизводимый результат важнее красивого

> Воспроизводимый отрицательный результат полезнее, чем красивый
> benchmark, который нельзя повторить. — из [08-exvram](../docs/08-exvram.md)

Правила замера:

| Правило | Почему |
|---|---|
| Медиана пяти прогонов, не лучший | Один удачный запуск не результат |
| Фиксировать заполненность контекста | `ctx-size 8192` может содержать 266 токенов |
| Не удалять неудачные эксперименты | История важнее подборки |
| «Без потери качества» не писать без gate | Формулировка закрывается измерением, не верой |

Ошибочный результат, который не воспроизвёлся, — это результат.
Записать его, а не выбросить.

Результат считается воспроизводимым, только если он **наш**. Чужое
измерение на чужом железе не воспроизводится у нас по определению —
см. правило 23.

---

## 18. Отказ модели — измеряемая величина

`refusal_rate` и `benign_over_refusal_rate` — разные метрики,
смешивать нельзя.

| Отказ | Что делаем |
|---|---|
| На безобидной задаче | Это дефект. Модель или рецепт меняется |
| На разрушительном действии | Работает как надо. Уровень доступа и L1-подтверждение |

Модель, отказывающая на «найди PDF на рабочем столе», ломает продукт.
Модель, отказывающая на «удали этот файл», — это правильное поведение,
которое мы подстраховываем слоем инструментов.

Цель: низкий `benign_over_refusal_rate` при высоком `refusal_rate`
на разрушительных.

---

## 19. Свой низкоуровневый код — только по измеренной причине

> Новый low-level код появляется только после того, как найден конкретный
> измеренный bottleneck, который существующий OSS-стек закрыть не может.

Сначала апстрим llama.cpp и существующие кванты. Сборка форка, свой
kernel, свой inference — после того как замер показал, что апстрим
не справляется. Иначе поддерживать чужую форк-ветку вместо своего кода.

---

## 20. Повторяемое — в код, а не в рассуждение

Модель вызывает **операцию**, а не собирает её из вызовов инструментов
каждый раз.

```rust
// Плохо: 8 вызовов инструментов, токены на каждом шаге
// Хорошо: 1 вызов, ноль токенов внутри
fn open_and_fill(app: &mut AppSession, data: FormData) -> Result<Operation>
```

| Что | Где |
|---|---|
| Операция | типизированная функция в `tools/operations/` |
| Примитивы | `click_element`, `type_text` — кирпичики внутри |
| Повтор | внутри операции, с лимитом попыток |
| Проверка | обязательна в конце каждой операции |

**Не собираем в операции то, что зависит от суждения модели.**
«Найди три подходящих PDF и разложи их» — решение модели плюс вызов
операции для перемещения.

Причина: на 9B и 8 ГБ VRAM десятишаговый сценарий через вызовы
занимает 30–90 секунд. Через операцию — секунда и ноль токенов.

---

## 21. Модель не тратит контекст на «а попробую по-другому»

Если действие упало, повтор делает код операции. Модель получает
результат: успех, или сдача с причиной.

Считать варианты в рассуждении модели — расход контекста без
пользы. Идея из AUV: `retry_until_verified`.

---

## 22. Промпт — дерево компонентов с бюджетом, не склейка строк

Каждый блок системного промпта умеет:

| Свойство | Зачем |
|---|---|
| Вернуть `None` | блок не нужен, не попадает в промпт |
| Иметь потолок по токенам | не съест контекст, даже если разросся |
| Рендериться детерминированно | один и тот же промпт из одних данных |

На 32K-профиле переполнение одного блока не должно вытеснять
остальные.

---

## 23. Число в коде — это измерение на нашем железе

**Правило:** любая цифра в коде, на которую опирается решение, должна
быть получена запуском на нашем железе. Если нет — это мнение, и
пишется как мнение, а не как факт.

| Что в коде | Должно быть |
|---|---|
| Порог, выше которого что-то отвергается | измерен на нашем железе |
| Просадка скорости, множитель | наш замер в [10-замеры](../docs/10-замеры.md) |
| Значение по умолчанию | проверено тестом на реальном файле |
| Число слоёв, слов, параметров | сверено с источником, со ссылкой |

### Три случая, из-за которых правило появилось

Все три нашлись за один день, и все три выглядели как проверенные.

| Было в коде | На самом деле |
|---|---|
| «offload стоит 6–8 раз» — ошибка при любом неполном размещении | Число из статьи ExVRAM. Свой замер: 28 слоёв из 33 стоят **1.84×** и работают |
| `enabled` по умолчанию `true`, комментарий «запрет по умолчанию» | Код разрешал всё. Комментарий и документация говорили обратное |
| Шаг 5 знакомства описан в плане как проверяемый | Проверять было нечем: инструментов нет |

### Почему это правило, а не пожелание

Направление ошибки несимметрично.

**Число из чужого источника в коде** — мы наследуем чужие условия
и принимаем решение на чужом железе. В первом случае это стоило
пользователю с 8 ГБ рабочего варианта, который мы сами у него отняли.

**Наше измерение устареет** — и это поправимо: повторить и записать
новое.

Значит цена ошибки несимметрична, и правило должно быть строгим к
первому случаю.

### Как отличить своё от чужого

Чужое число узнаётся по формулировке. Обычное дело — «стоит 6–8 раз»,
«в 2 раза медленнее», «занимает почти всю память» без указания, где
получено.

Своё число узнаётся по трём признакам:

| Признак | Пример |
|---|---|
| Железо названо | RTX 5060 8 ГБ, 32 ГБ RAM |
| Условия названы | `-ngl 28`, KV `q4_0`, контекст 8K |
| Повторов и разброс | 3 повтора, ± 0.35 |

Если хотя бы одного признака нет — число переносимое, а не
передаваемое другим людям.

### Ссылка обязательна

Число в коде без указания, откуда оно, читается как истина. Значит
рядом должен быть либо замер в [10-замеры](../docs/10-замеры.md),
либо слово «предположительно».

Примеры правильной формы:

```rust
// По замеру 12.10.2026, docs/10-замеры.md: 28 из 33 слоёв на GPU
// стоят 1.84×, 20 из 33 — уже 3.22×. Пороги взяты от этих точек.
if share >= 0.80 { Offload::Mild }
```

```rust
// Предположительно: порог взят из документации, своего замера нет.
let timeout = Duration::from_secs(30);
```

### Связь с остальными правилами

Правило 17 требует воспроизводимости результата. Это правило требует,
чтобы результат был **нашим** — иначе он не воспроизводим на нашем
железе в принципе.

Правило 15 запрещает непроверенные лицензии. Здесь то же самое про
числа: непроверенное число не используем как основание для решения.

### Что делать, когда измерить нечем

Не измерили — пишем «не измерено» и оставляем поведение
консервативным. Пример: T1 на 8 ГБ RAM. Мы не можем утверждать, что
профиль реален, поэтому не объявляем его рабочим, а помечаем
гипотезой.

Отказ изменить поведение без измерения — это тоже решение.
Просто оно должно быть записано как решение, а не как факт о железе.
