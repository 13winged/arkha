# Hermes Agent — что можно взять

Разбор [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent).

Сравнение с ODS как референсом и решение — использовать или перенимать.

---

## Главное: лицензия MIT

| Проект | Лицензия | Что можно |
|---|---|---|
| ODS (корень) | Apache-2.0 | копировать с атрибуцией |
| ODS `vendor/pixel` | ODS-only grant | **только внутри ODS** |
| **Hermes Agent** | **MIT** | **копировать, менять, использовать в коммерции** |

MIT снимает главное ограничение, которое мы обсуждали: агентный рантайм
ODS копировать нельзя, Hermes — можно.

Это меняет баланс референсов. Hermes полезнее ODS как источник кода,
потому что под тем же Apache мы всё равно писали бы агент с нуля.

## Что брать

### 1. Декомпозиция состояния

Самое ценное. 28 отдельных модулей `hermes_state_*`:

```
hermes_state_compression.py      ← сжатие
hermes_state_guard.py            ← охрана
hermes_state_health.py           ← здоровье
hermes_state_identity.py         ← идентичность
hermes_state_lockguard.py        ← защита блокировок
hermes_state_lockowners.py       ← владельцы блокировок
hermes_state_maintenance.py      ← обслуживание
hermes_state_messages.py         ← сообщения
hermes_state_portability.py      ← переносимость
hermes_state_readpool.py         ← пул чтения
hermes_state_registry.py         ← реестр
hermes_state_repair.py           ← починка
hermes_state_rewind.py           ← откат
hermes_state_schema.py           ← схема
hermes_state_search.py           ← поиск
hermes_state_sessions.py         ← сессии
hermes_state_profile_repair.py   ← починка профиля
hermes_state_error*.py           ← ошибки
```

**Зачем нам:** мы планировали написать свой `state` одним файлом. Это
ошибка. Разделение на 28 модулей — признак системы, где состояние
переживает падения, гонки и повреждения.

Конкретные идеи для переноса:

| Модуль | Идея |
|---|---|
| `state_health` | самопроверка целостности состояния, а не только «файл существует» |
| `state_repair` | автоматическая починка при повреждении |
| `state_lockguard` + `state_lockowners` | кто держит блокировку, защита от зависших блокировок |
| `state_rewind` | откат состояния к точке. У нас нет ничего подобного |
| `state_portability` | перенос состояния между машинами |
| `state_identity` | идентификация сессии, устойчивая к перезапуску |

**`state_rewind` — самое интересное.** Откатить действия агента к
состоянию «до». У нас в проекте есть readback и отмена выполнения, но
не откат уже сделанного. Это разные вещи: отмена прерывает текущую
работу, rewind возвращает систему в прошлое.

### 2. Реестр инструментов и тулсеты

`hermes tools` — конфигурация того, какие инструменты включены.

Это ровно то, чего не хватало нам. В Brainstorm2 п.2 я записал
«реестр возможностей с проверкой доступа» как недостающую деталь.
У Hermes это уже решено: тулсеты, включаемые пользователем.

**Забираем:** систему тулсетов с проверкой доступа и объяснением,
почему инструмент недоступен.

### 3. Навыки в формате agentskills.io

> Compatible with the [agentskills.io](https://agentskills.io) open standard

У нас был свой формат `skills/*/SKILL.md`. Hermes уже совместим со
стандартом. **Не изобретать свой — использовать существующий.**

Это экономит работу и даёт совместимость с чужой экосистемой навыков.

### 4. Антивирус и ложные срабатывания

Целый раздел в README: Windows Defender и Bitdefender флагают `uv.exe`
как малварь. Разбирает, как проверить подлинность, как добавить
исключение, почему папку а не хэш файла.

**Это подтверждает нашу проблему п.10 из Brainstorm2 и даёт готовое решение.**
У нас будет `llama-server.exe` — тоже unsigned-бинарь, тоже полетит
в карантин. Сценарий «антивирус удалил бинарь, модель не грузится,
пользователь не понимает почему» — ровно тот же.

Что забрать:
| Приём | Применение |
|---|---|
| Проверка подлинности через attestation | для llama.cpp |
| Инструкция по добавлению исключения | в диагностику |
| Исключение на папку, не на файл | обновления ломают хэш |
| Явное «это ложное срабатывание» | в сообщении об ошибке |

### 5. Диагностика `hermes doctor`

Команда для диагностики проблем. У нас есть «Диагностика» в планах,
но как отдельный инструмент CLI с проверками — полезный паттерн.

### 6. FTS5 для поиска по сессиям

> FTS5 session search with LLM summarization for cross-session recall

Встроенный полнотекстовый поиск по истории разговоров с суммаризацией
результатов. У нас в Brainstorm2 п.5 «журнал как функция» с поиском
«что я просил на прошлой неделе».

**Забираем:** FTS5, а не sqlite-vec, для лексического поиска по диалогам.
Это разные задачи: векторный поиск для документов, FTS5 для своей
истории.

Плюс: у них есть `native/fts5_cjk` — нативное расширение FTS5 для CJK.
Для русского это не нужно, но показывает подход: если стандартный
токенизатор не справляется, пишут нативное расширение. Для русского
может понадобиться стемминг или ICU.

### 7. Модель предоставления разрешений

Из документации: command approval, DM pairing, container isolation.

`DM pairing` — привязка по идификатору пользователя. У нас для Telegram
это было в планах как «ограничение по chat id». У Hermes это штатная
сущность.

### 8. Переключение моделей без изменения кода

> Switch with `hermes model` — no code changes, no lock-in

У нас это есть (профиль → модель), но Hermes делает это через единую
абстракцию провайдера: `hermes model` работает с любым провайдером и
любой локальной моделью одинаково.

**Забираем:** слой провайдера с единым интерфейсом. Их `providers/`
покрывает и OpenRouter, и OpenAI, и свой endpoint.

### 9. Техника «скрипты вызывают инструменты по RPC»

> Write Python scripts that call tools via RPC, collapsing multi-step
> pipelines into zero-context-cost turns

Модель пишет скрипт, который сам вызывает инструменты. Конвейер из
пяти шагов сворачивается в один ход без расхода контекста.

**Это умнее, чем просто типизированные инструменты.** Думал об этом
как о возможности, но не оформил. Стоит забрать идею: для повторяющихся
конвейеров не гонять каждый шаг через модель.

### 10. Управление контекстом через slash-команды

| Команда | Что делает |
|---|---|
| `/compress` | сжатие контекста |
| `/usage` | расход |
| `/insights [--days N]` | аналитика за период |
| `/undo`, `/retry` | откат хода |
| `/skills` | просмотр навыков |

Паттерн хороший: пользователь видит расход и может вручную сжать
контекст. У нас compaction автоматический — добавление ручного
триггера полезно для отладки.

## Что НЕ брать

| Репозиторий / модуль | Почему |
|---|---|
| Python как рантайм | мы делаем Rust + Tauri. Один `.exe` против Python + Node + uv + ripgrep + FFmpeg |
| Терминальный TUI как основной UX | наш продукт — десктопное приложение с голосом |
| `uv.exe` как зависимость | unsigned-бинарь, вызывает ложные срабатывания антивируса |
| 40+ инструментов из коробки | 9B на 8 ГБ VRAM. Инструменты дешёвые для модели, нужно 5–8 точных |
| Контейнерные бэкенды (Docker, Singularity, Modal, Daytona, Vercel) | мы убрали Docker сознательно. Modal и Daytona — облако, у нас hybrid |
| `Honcho` для моделирования пользователя | отдельная зависимость. Проще свой профиль в JSON |
| ACP-адаптер | поддержка чужого протокола. Не наша задача |
| Исследовательский трекинг (`evals/`, `batch_runner`) | это про обучение моделей, не про продукт |

## Стратегический вопрос: использовать или перенимать

Тут стоит остановиться, потому что ответ меняет план.

### Аргументы за «просто использовать Hermes»

| Аргумент | Вес |
|---|---|
| MIT, можно встраивать в коммерческий продукт | сильный |
| 40+ инструментов уже написаны и отлажены | сильный |
| Telegram, Discord, Slack, WhatsApp, Signal | сильный |
| Обучение, навыки, память, cron — всё есть | сильный |
| Нативный Windows, PowerShell-установщик | средний |
| Наша задача S5 (агентный рантайм) — 4–5 дней работы | средний |

### Аргументы за «перенимать»

| Аргумент | Вес |
|---|---|
| Поставка: один `.exe` без терминала против Python + Node + uv + ripgrep + FFmpeg | сильный |
| UX: десктоп-приложение с голосом против TUI | сильный |
| Windows-инструменты: UIA, COM. У них только `computer-use-linux` MCP для Linux | сильный |
| Модель 9B на 8 ГБ. Hermes явно проектировался под сильные модели | сильный |
| Проактивность на своём железе, без `$5 VPS` | средний |
| Управление размером промпта под 16K контекста | средний |
| Наша архитектура уже спроектирована и непротиворечива | средний |

### Вывод

**Перенимать, не использовать.**

Причина одна и достаточная: продукт определяется поставкой. «Один `.exe`,
который работает на 8 ГБ RAM» и «Python-стек с пятью зависимостями на
VPS» — это разные продукты для разных людей. Наш целевой пользователь —
средний, без терминала.

Hermes как референс лучше ODS: MIT, нативный Windows, ближе к нашей
задаче, решает многие из наших открытых вопросов уже решёнными.

**Но его `state`-слой и навыки — прямая находка.** Декомпозиция на 28
модулей и формат agentskills.io экономят нам дни работы и дают качество,
которое иначе пришлось бы изобретать.

## Один вопрос, который я задам себе

Мы уже пять документов, ни одной строки кода, и каждая итерация
добавляет ещё один референс.

Стоит остановиться и начать S0. Материала достаточно: архитектура
спроектирована, этапы расписаны, референсы изучены, лицензия вопроса
по агентному рантайму больше не стоит.

Единственное, чего не хватает — один реальный сценарий пользователя.
Но это вопрос к тебе, не ко мне.
