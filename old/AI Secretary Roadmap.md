Дорожная карта локального ИИ-секретаря на Windows.

Своё приложение. ODS — референс для инженерных решений, не зависимость.
Стек описан в [AI Secretary Stack.md](AI%20Secretary%20Stack.md).

---

## Задачи секретаря (приоритет)

1. Общаться с пользователем — голос и текст
2. Отвечать на вопросы
3. Читать интернет — поиск и разбор страниц
4. Управлять ПК — UI Automation
5. Работать с документами — RAG

Первые четыре не требуют RAG. Документы — Фаза 7, потому что индексация
корпуса это отдельная операция, а не то, что секретарь делает в моменте.

---

## Аудитория

Неоднородный парк машин. Пять профилей, определяются автоматически.

| Профиль | RAM | VRAM | Модель | Контекст |
|---|---|---|---|---|
| T1 | 8 ГБ | встройка / 4 ГБ | Qwen3.5 4B Q4 | 16K |
| T2 | 16 ГБ | 8 ГБ | Qwen3.5 9B Q4_K_M | 32K |
| T3 | 32 ГБ | 8 ГБ | Qwen3.5 9B Q5_K_M | 64K |
| T4 | 32 ГБ | 12–16 ГБ | Qwen3.5 27B Q4_K_M | 128K |
| T5 | 64 ГБ+ | 24 ГБ+ | Qwen3.5 27B Q4_K_M | 262K |

**Проверка на всех профилях встроена в каждую фазу**, а не вынесена в конец.
Иначе обнаружится, что T1 сломан, когда код уже весь написан.

## Фаза 0 — Лицензии и референс

**Цель:** понять, что можно взять, а что придётся писать с нуля.
**Результат:** список решений для переноса и чёткая граница «нельзя копировать».

### Шаги

- [ ] Прочитать ODS `MODEL-MANAGEMENT.md` — как устроен каталог и выбор модели
- [ ] Прочитать ODS `PIXEL.md` — устройство агента, approvals, отмена
- [ ] Проверить лицензию Pixel: грант ODS-only, standalone исключён
- [ ] Проверить лицензии: llama.cpp, Tauri, sqlite-vec, faster-whisper, Kokoro,
      Silero, openWakeWord, SearXNG, UI Automation crate
- [ ] Выписать список решений для переноса в свой код (раздел 9 стека)
- [ ] Зафиксировать, что Portal/Pixel не копируется

### Гейт

Список из ~10 переносимых идей и подтверждённые лицензии на всё, что
планируем использовать. Если лицензия неясна — не используем.

**Почему первым:** ошибка в лицензиях обнаруживается на этапе публикации,
когда переделка стоит дороже всего.

## Фаза 1 — Профиль железа и inference

**Цель:** приложение запускается, определяет профиль, отвечает текстом.
**Результат:** работающий чат на всех профилях.

### Шаги

**Определение профиля**

- [ ] Запрос VRAM (DXGI / `nvidia-smi`), RAM (`GlobalMemoryStatusEx`), CPU
- [ ] Правило выбора T1–T5
- [ ] Каталог моделей в своём JSON
- [ ] Определение профиля сохраняется, переопределяется вручную

**Сайдкар llama.cpp**

- [ ] Сборка `llama-server` как отдельного процесса
- [ ] OpenAI-совместимый эндпоинт
- [ ] Запуск с `--tool-call-parser qwen3_coder`
- [ ] Контекст и KV-кэш по профилю, квант `q8_0`
- [ ] Проверка готовности реальным запросом, не фактом старта процесса

**Модель-менеджер**

- [ ] Скачивание GGUF с проверкой digest каждого файла
- [ ] Проверка: архитектура, размер, комплектность
- [ ] Bootstrap-режим: 4B сразу, большая модель в фоне
- [ ] Транзакционная смена: при провале вернуть предыдущую

**Каркас приложения**

- [ ] `npm create tauri-app` — React + TS + Vite
- [ ] Управление жизненным циклом сайдкара
- [ ] Экран чата: сообщения, стрим, индикатор модели и профиля
- [ ] Лог действий в отдельной панели
- [ ] Настройки: профиль, контекст, endpoint
- [ ] Thinking mode выключен, `enable_thinking: false`

### Гейт

На трёх машинах: приложение запускается, определяет профиль, стримит ответ.
На T1 и T2 модель грузится и проходит проверочный запрос.

## Фаза 2 — Agent runtime

**Цель:** модель вызывает инструменты и действует в цикле.
**Результат:** «открой блокнот», «напиши в файл текст», «что здесь написано».

### Шаги

**Tool registry**

- [ ] Объявление инструментов с JSON-схемами
- [ ] Lean tool surface: `tool_search` / `tool_describe` / `tool_call`
- [ ] Никаких сырых команд от модели, только типизированные аргументы

**Executor**

- [ ] Цикл: рассуждение → вызов → результат → рассуждение
- [ ] Потолок шагов на один запрос
- [ ] Таймаут на вызов
- [ ] Обработка невалидного ответа модели

**Approvals**

- [ ] Уровни L1 / L2 / L3
- [ ] Модальное подтверждение для L1 и L2
- [ ] Уровни задаются пользователем, консервативные по умолчанию

**Receipts**

- [ ] Запись: что вызвано, с какими аргументами, какой результат
- [ ] Показ в логе действий

**Compaction**

- [ ] Бюджет истории по профилю
- [ ] Ужатие при приближении к лимиту
- [ ] Сохранение хвоста диалога и системного промпта

**Cancellation**

- [ ] Маркер запуска с SHA-256 от идентификатора
- [ ] Убийство process group, статус 130
- [ ] Проверка: отмена реально останавливает работу, а не только помечает

### Гейт

Модель сама выбирает инструмент по русской команде, получает результат,
продолжает работу. Отмена прерывает выполнение. Удаление файла требует
подтверждения и не происходит без него.

## Фаза 3 — Инструменты Windows

**Цель:** секретарь управляет ПК.
**Результат:** «что открыто», «открой почту», «введи текст».

### Шаги

**Окна**

- [ ] Список открытых окон + заголовки (`EnumWindows`)
- [ ] Активация окна по заголовку
- [ ] Чтение дерева элементов (UIA)
- [ ] Клик по элементу, ввод текста (`Invoke` / `ValuePattern` + SendInput)

**Приложения**

- [ ] Запуск через `ShellExecuteW`
- [ ] Закрытие по PID

**Файлы**

- [ ] Листинг, чтение, поиск по имени и содержимому
- [ ] Создание файла (требует подтверждения)
- [ ] Пути нормализуются, выход за разрешённые каталоги блокируется
- [ ] Удаление — только в корзину, всегда с подтверждением
- [ ] Watching через `notify`

**Интернет**

- [ ] Поиск: SearXNG или свой HTML-парсер
- [ ] Чтение страницы: HTTP + парсинг в чистый текст
- [ ] Обрезка навигации, рекламы, скриптов

### Почему UIA, а не скриншоты

На T1–T2 (VRAM до 8 ГБ) vision вместе с контекстом не помещается.
UIA даёт структурированные данные — заголовки, тексты полей, состояния
кнопок — без обращения к GPU. Для задач «открыть», «ввести», «нажать»
этого достаточно.

На T4–T5 vision доступен, включается по профилю.

Инструмент «скриншот» на T1–T2 либо отсутствует в списке, либо объясняет
почему недоступен.

### Гейт

Пять сценариев проходят на всех профилях:

| Сценарий | Что проверяет |
|---|---|
| «Что сейчас открыто?» | список окон |
| «Найди все PDF на рабочем столе» | файловая система |
| «Открой последний» | запуск приложения |
| «Найди в интернете про X» | поиск |
| «Что написано на этой странице?» | чтение страницы |

Если сценарий не проходит на T1 — отключается по профилю с понятным
сообщением, а не падает с ошибкой.

## Фаза 4 — Голос

**Цель:** разговор без клавиатуры.
**Результат:** «Секретарь» → вопрос → голосовой ответ.

### Шаги

1. [ ] Захват микрофона (`cpal`) + кольцевой буфер
2. [ ] VAD Silero — детект границ речи
3. [ ] STT faster-whisper, модель по профилю
4. [ ] TTS Kokoro
5. [ ] Цикл без wake-word: кнопка «слушать»
6. [ ] openWakeWord — детект wake-фразы
7. [ ] Индикатор состояния: слушаю / думаю / говорю
8. [ ] Barge-in: перебивание на ходу речи
9. [ ] Проверка эха перед перебиванием

### Порядок сборки

Сначала запись аудио → файл → STT текстом. Убедиться что слышно.
Потом TTS текстом → файл → воспроизведение. Потом цикл с VAD.
Потом wake-word. Потом barge-in.

Не пытаться делать всё сразу — невозможно понять, где сломалось.

### По профилям

| Профиль | STT | Цикл |
|---|---|---|
| T1 | `tiny` на CPU | 3–6 сек |
| T2 | `base` | 1.5–3 сек |
| T3+ | `small` на GPU | <1–2 сек |

### Гейт

Полный цикл голосового диалога. Перебивание останавливает ответ.
Работает на T1–T3.

## Фаза 5 — Память

**Цель:** секретарь помнит пользователя между сессиями.

### Шаги

- [ ] Профиль пользователя: JSON, загрузка при старте
- [ ] Долговременные факты в sqlite-vec, отдельная коллекция
- [ ] Извлечение фактов из диалога — только явные предпочтения
- [ ] Консоль памяти: посмотреть / исправить / удалить
- [ ] Бюджет по профилю: T1 без долговременной памяти

### Ограничение

Писать только то, что модель явно решила запомнить. Сырой лог диалогов
в базу не писать — через месяц качество поиска упадёт.

### Гейт

Персонализация работает между сессиями. «Что я говорил про X» находит факт.

## Фаза 7 — Документы и RAG

**Цель:** секретарь знает содержимое документов.
**Результат:** «что в этом PDF» по названию файла.

### Шаги

- [ ] Выбор корпуса (папка с PDF/DOCX/MD)
- [ ] Индексация: извлечение текста, чистка
- [ ] Чанкинг по структуре — заголовкам, не фиксированному размеру
- [ ] Эмбеддинги BGE-M3 (ONNX) в процессе
- [ ] Запись в sqlite-vec, коллекция корпуса
- [ ] Поиск: Top-K по профилю (раздел 5.7 стека)
- [ ] Переиндексация изменённых файлов через `notify`
- [ ] Цитирование источников с именем файла
- [ ] UI: выбор корпуса, прогресс, статистика

### Важно

Индексация — офлайн-процесс. Разбор PDF на каждый запрос нельзя.

**RAG должен укладываться в контекст.** На T2: система ~2K, история ~16K,
RAG-выборка ~6K, резерв под ответ. Top-K больше 6–8 чанков вызовет OOM
при длинной истории. Это частая причина проблем.

### Гейт

Вопрос по содержимому документа даёт верный ответ со ссылкой на файл.

## Фаза 8 — Облачный fallback

**Цель:** сложные задачи не упираются в локальную модель.

### Шаги

- [ ] Три режима: local / hybrid / cloud
- [ ] По умолчанию local, переключение явно
- [ ] Правила маршрутизации: многошаговый план, длинный контекст
- [ ] Показывать пользователю, когда запрос ушёл в облако
- [ ] Ключ в DPAPI, локально
- [ ] История облачных вызовов

### Гейт

Сложная задача доходит до ответа. Индикатор показывает облачный вызов.

## Фаза 9 — Установщик и распространение

**Цель:** обычный пользователь ставит софт в один шаг, без терминала.

### Шаги

- [ ] Один установщик: приложение + сайдкар llama.cpp
- [ ] Скачивание модели при первом запуске, с прогрессом
- [ ] Проверка предусловий до изменений
- [ ] Откат при неудачной установке
- [ ] Понятные сообщения об ошибках, без стектрейсов
- [ ] Ярлык на рабочем столе
- [ ] Кнопка «Диагностика» — отчёт с конкретным действием
- [ ] Автообновление приложения
- [ ] Логи с ротацией

### Тест на чистой машине

Обязательно: установить на чистую Windows без подготовки. Это то, что
увидит пользователь. Никаких Docker, WSL2, ручных шагов с моделью.

### Гейт

Человек, который никогда не открывал терминал, устанавливает софт
и получает работающего секретаря.

## Риски

| Риск | Влияние | Что делать |
|---|---|---|
| Лицензия неясна | Нельзя распространять | Фаза 0, не использовать непонятное |
| Профиль определён неверно | Не та модель, OOM | переопределение в UI, пересчёт бюджетов |
| T1 (8 ГБ RAM) тормозит | Плохой UX | модель 4B, отключить память и напоминания |
| 8 ГБ VRAM не хватает на 32K | OOM в длинном диалоге | `Q4_K_S`, KV-кэш q4, либо контекст 16K |
| RAG-выборка съедает контекст | OOM при длинной истории | Top-K по профилю, лимит на чанк |
| Скорость ниже 20 tok/s | Диалог неприемлем | hybrid-режим |
| Русский в Qwen3.5 хуже ожиданий | Плохой UX | запасная модель Gemma 4 |
| Модель не вызывает нужный инструмент | Задача не выполняется | узкие инструменты, lean search, подтверждения |
| Функция работает на T3, падает на T1 | Половина пользователей без функции | проверка на трёх профилях в каждой фазе |
| Сайдкар падает | Нет ответов | рестарт с ограничением попыток, откат модели |
| Установщик ломает систему | Пользователь не откатит | проверка предусловий, откат |
| «Отмена» только помечает | Пользователь ждёт, а работа идёт | маркер запуска + убийство process group |

## Что проверить в первую очередь

1. **Лицензии** (Фаза 0) — определяет, что вообще можно распространять
2. **Скрипт определения профиля** — самая ранняя зависимость
3. **Поведение на T1** — нижняя граница решает, какие функции доступны
   половине пользователей
4. **Реальные задачи пользователя** — 5–10 конкретных сценариев для Фазы 3

Первые три проверяются за неделю. Четвёртое — наполнение Фазы 3.
