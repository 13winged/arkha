# Project AIRI — что можно взять

Реверс [moeru-ai/airi](https://github.com/moeru-ai/airi) и связанных
подпроектов.

Для сравнения: [Hermes](AI%20Secretary%20Hermes.md) — референс для
агентного рантайма, ODS — для модели-менеджера и идей по безопасности.

## Что берём

### 1. `webai-realtime-voice-chat` — голос, почти в одном файле

> Full example of implementing ChatGPT's realtime voice from scratch
> with VAD + STT + LLM + TTS technology stack within almost one file!

MIT, 187 звёзд. Четыре инкрементальных демо:

| Демо | Что добавляет |
|---|---|
| VAD | детект границ речи |
| VAD + ASR | распознавание |
| VAD + ASR + LLM | диалог |
| VAD + ASR + LLM + TTS | полный цикл |

**Это ровно наш S9 «Голос», но эталонный и пошаговый.** У нас в плане
тот же порядок сборки: запись → STT → TTS → цикл с VAD → wake-word →
barge-in. Здесь то же самое, реализовано и проверено.

Забрать: архитектуру пайплайна и инкрементальный подход. Не код —
он на TypeScript в браузере, у нас Rust нативно.

### 2. `pipelines-audio` — мультипровайдерный голос

Список из README: ElevenLabs, Microsoft/Azure Speech, OpenAI-compatible
TTS, Alibaba Cloud Model Studio, **локальный Kokoro**.

Полезная деталь: у них один интерфейс на все провайдеры, включая локальный.
У нас в плане один Kokoro, но если пользователь захочет облачный голос для
качества — переключение без переписывания.

Забрать: единый интерфейс `TTSProvider` с локальным и облачными
реализациями.

### 3. Разделение `desktop_*` и `browser_dom_*`

Из `computer-use-mcp`:

> Use the two surfaces differently: `desktop_*` for native apps,
> `browser_dom_*` for real browser pages

Плюс третий путь — `browser_agent_run` для целевых задач, где агент
сам исследует страницу.

| Инструмент | Для чего |
|---|---|
| `desktop_*` | нативные приложения, окна, ввод |
| `browser_dom_*` | страницы браузера, формы, iframe |
| `browser_agent_run` | делегировать веб-цикл целиком |

**У нас этого нет вообще.** Мы думали «UIA для всего». На веб-страницах
DOM даёт селекторы и значения — это надёжнее координат и не жжёт VRAM.

Плюс приоритет исполнения из их README:

> prefers deterministic execution paths before raw coordinate actions

Это совпадает с нашим выводом UIA-first, но формулирует точнее.

### 4. Протокол approvals через MCP

Цепочка из пяти шагов:

1. Модель вызывает инструмент
2. MCP возвращает `approval_required`
3. UI показывает нативный диалог
4. Приложение вызывает `approve` или `reject`
5. Разрешение переиспользуется для текущего запуска

Пятый пункт важный: **одно подтверждение на серию действий**, не на каждое.
Это ровно то, что мы записали как «план → подтверждение» в Brainstorm §6,
но здесь это протокол, а не идея.

Забрать: протокол `approval_required` + переиспользование разрешения
в пределах запуска.

### 5. `COMPUTER_USE_APPROVAL_MODE`

```bash
COMPUTER_USE_APPROVAL_MODE=actions   # по умолчанию
COMPUTER_USE_APPROVAL_MODE=all       # всё подтверждать
COMPUTER_USE_APPROVAL_MODE=never     # ничего не подтверждать
```

Плюс политика приложений:

```bash
COMPUTER_USE_OPENABLE_APPS=Terminal,Cursor,Google Chrome
COMPUTER_USE_DENY_APPS=1Password,Keychain,System Settings,AIRI
```

И **AIRI в собственном deny-листе** — агент не может управлять собой.

У нас концепт тот же (`permissions.json`), но список запрещённых приложений
стоит добавить: менеджеры паролей, настройки системы, сам секретарь.

### 6. `dry-run` как режим по умолчанию

> `dry-run` — default, never injects input, still captures screenshots

Пока пользователь не включил реальное исполнение, агент наблюдает
и показывает, что *сделал бы*. Скриншоты сохраняются для отладки.

Отличный паттерн для онбординга: пользователь сначала видит
«я бы открыл это окно и нажал сюда», потом включает реальное действие.

Забрать: режим по умолчанию — наблюдение. Включение действий — осознанно.

### 7. `audit.jsonl` и `trace` по запуску

Отдельные артефакты: `report.json`, `audit.jsonl`, скриншоты, `trace`.

Их рекомендация по демо:

> End by opening the generated report.json, audit.jsonl, or screenshots
> so the demo finishes with evidence rather than just screen motion.

Это наш пункт «журнал как функция» из Brainstorm2 п.5, реализованный.

Забрать: формат артефактов. `audit.jsonl` — append-only журнал, его
можно читать и без приложения. Плюс скриншоты после каждого действия.

### 8. Три режима исполнения

```bash
COMPUTER_USE_EXECUTOR=dry-run
COMPUTER_USE_EXECUTOR=macos-local
COMPUTER_USE_EXECUTOR=linux-x11
```

Мы добавляем `windows-local`. Паттерн: режим исполнения конфигурируемый,
не зашитый.

### 9. `xsai` — минимальный клиент провайдеров

> Implemented a decent amount of packages to interact with LLMs and models,
> like Vercel AI SDK but way small

Поддерживает 30+ провайдеров, включая vLLM, SGLang, Ollama,
OpenAI-compatible, Anthropic, Qwen, Mistral.

У нас это своя обёртка над llama-server. Их слой полезен тем, что
провайдер — это дескриптор, а не код. Смена провайдера = смена дескриптора.

### 10. `inventory` — каталог моделей

Отдельный сервис: centralized model catalog and default provider
configurations.

У нас `profiles.json` — то же самое, но наше. Идея «каталог как
отдельный сервис» полезна, если захотим делиться настройками
между устройствами.

### 11. `unspeech` — прокси для аудио

> Universal endpoint proxy server for /audio/transcriptions and /audio/speech,
> like LiteLLM but for any ASR and TTS

LiteLLM для аудио. У нас это «быстрая модель для фоновых задач» —
своё решение в обход LiteLLM. Их подход: единые эндпоинты,
любой бэкенд под ними.

### 12. `inventory` + `demodel` — доставка моделей

- `demodel` — ускорение скачивания моделей и датасетов
- `inventory` — каталог и дефолтные конфигурации провайдеров

У нас свой модель-менеджер с проверкой digest. `demodel` решает
ту же проблему быстрее. Стоит посмотреть при реализации S2.

## Что НЕ берём

| Часть | Почему |
|---|---|
| `computer-use-mcp` целиком | macOS-only: `NSWorkspace`, `CGWindowList`, Quartz `CGEvent`. Windows нужно писать на UIA и SendInput |
| Vue как фреймворк UI | мы на React + Tauri. Миграция не стоит выгоды |
| Electron | мы на Tauri. ~250 МБ против ~40 МБ |
| WebGPU-инференс в браузере | «a different kind of fun». Плюс нет доступа к ПК |
| VRM и Live2D | цифровой компаньон, не секретарь |
| Minecraft, Factorio, Kerbal | не наша задача |
| `stage-pocket` (мобильный) | нет смысла, есть Telegram |
| Дизайн и аватарки | не наш продукт |
| Staged Tamagotchi как терминология | наш продукт — «секретарь» |
| Caddy, PostgreSQL, Redis, auth-server | их серверная часть. У нас нативно и без бэкенда |

## Сравнение референсов

| Проект | Лицензия | Что полезнее для нас |
|---|---|---|
| ODS | Apache-2.0, Pixel — ODS-only | модели, установка, безопасность, approvals |
| Hermes Agent | MIT | агентный рантайм, состояние, навыки, антивирус |
| **AIRI** | **MIT** | **голос, computer-use, approvals, аудит** |
| AirLLM | Apache-2.0 | ничего, отклонён |
| CopilotKit | — | генеративный UI, идея |

**AIRI — лучший источник по компьютерному управлению и голосу.**
Hermes — лучший по агентному рантайму. ODS — по модели-менеджеру
и безопасности.

Из `computer-use-mcp`:

И:

> Less convincing demos: long videos of coordinate clicking with no

То же, что мы вывели сами в Brainstorm п.5 и п.10, но сформулировано
раньше и чётче. Полезное подтверждение: мы на верном пути в том, что
считаем ценным.

### Изменения в S3 — разрешения

```json
{
  "deny_apps": ["1Password", "KeePass", "Параметры", "Secretary"],
  "approval_mode": "actions",
  "executor": "dry-run"
}
```

`deny_apps` — приложения, которые агент не может открыть, сфокусировать
или в которые не может ввести текст. Никогда, даже при полном доступе.

Секретарь в своём deny-листе обязателен: агент не должен управлять
собственным интерфейсом — это путь к зацикливанию.

### Изменения в S4 — знакомство

Добавить шаг: сначала `dry-run`, пользователь видит что агент
сделал бы, потом включает реальные действия. Это безопаснее и понятнее,
чем сразу давать доступ.

### Изменения в S6 — инструменты

Два набора инструментов вместо одного:

| Набор | Куда | На чём |
|---|---|---|
| `desktop_*` | нативные приложения | UIA, Win32 |
| `browser_dom_*` | страницы браузера | расширение или WebDriver |

## Честная оценка

AIRI — VTuber-проект с сообществом, дизайнерами, спонсорами. Их код
оптимизирован под живое общение: LowLatency, WebGPU, аниме-девушки.

Но **подсистемы у них сделаны правильно**: разделение поверхностей,
протокол approvals, append-only аудит, dry-run по умолчанию, явный deny-list.
Это не бытовой код, а инженерные решения, которые набили шишки.

Мы делаем секретаря, а не компаньона. Но эти подсистемы переносимы
без изменений.

   голос, approvals-протокол и browser DOM. Это меняет приоритеты
   этапов — нужно пересобрать `Stages.md`.

   перебор. Дальше каждая новая находка всё меньше влияет на решение.
3. **Когда начинать код.** Материала достаточно. S0, S1, S2 не изменились
   ни одним из рассмотренных проектов — они про Tauri, профиль и llama.cpp.
