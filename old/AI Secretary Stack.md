# AI Secretary — стек

Локальный ИИ-секретарь на Windows: голос, доступ к ПК, документы, память.

Своё приложение. ODS используется как **референс** — источник проверенных
решений, а не как зависимость в рантайме.

---

## 1. Что значит «ODS как референс»

Берём инженерные решения и подходы, не код агента.

| Из ODS берём идею | Что именно |
|---|---|
| Каталог моделей | `model-library.json` + селектор по профилю железа |
| Tиры железа | деление по VRAM/RAM с детерминированным выбором |
| Bootstrap-режим | маленькая модель сразу, большая грузится в фоне |
| Компакция памяти | потолок хвоста, резерв под вывод, пересчёт бюджета |
| Отмена исполнения | маркер запуска + убийство process group, статус 130 |
| Карантин артефактов | изоляция загрузок, проверка по digest перед публикацией |
| Идентичность файлов | привязка к точному хэшу, fail closed при расхождении |
| Lean tool surface | отдавать модели не все схемы сразу, а поиском по инструментам |
| Транзакционная смена модели | новый runtime проверяется, при провале откат на прошлый |

Не берём: код Portal/Pixel, его промпты, его политики. Это под отдельной
лицензией (раздел 2).

---

## 2. Лицензии — проверить до копирования

Это ограничение определяет, что вообще можно переиспользовать.

| Компонент | Лицензия | Что можно |
|---|---|---|
| ODS (корень) | Apache-2.0 | копировать с атрибуцией, сохранять NOTICE |
| ODS `vendor/pixel` | Pixel License for ODS | **только внутри ODS, не как отдельный продукт** |
| Qwen3.5 | Apache-2.0 | свободно |
| Bonsai 27B | Apache-2.0 | свободно |
| Gemma 4 | Apache-2.0 | свободно |

**Pixel/Portal копировать нельзя.** Его грант прямо исключает standalone
использование. Значит агентный рантайм — наш собственный код: tool registry,
цикл исполнения, approvals, память, compaction.

**Перед копированием чего угодно проверить лицензию.** Для Hermes, OpenClaw,
SearXNG, Kokoro, faster-whisper, sqlite-vec и прочего — лицензии не проверялись,
делать это нужно отдельно.

Итого: у ODS берём подходы и паттерны, агент пишем с нуля.

### Почему без WSL2 и Docker

Отказ от ODS как рантайма убирает Docker Desktop и WSL2, и это главное
упрощение во всём проекте.

| | ODS в WSL2 | Свой нативный процесс |
|---|---|---|
| Установка | PowerShell → WSL2 → Ubuntu → Docker → ODS, **перезагрузка** | один `.exe`, без перезагрузки |
| Диск | 40 ГБ минимум | 15 ГБ (модель + бинарь) |
| RAM в простое | +2–4 ГБ на Docker и WSL2 | 0.4–0.6 ГБ |
| GPU | проброс Docker, лишний слой | прямой доступ |
| Пути Windows | кривые права и пути | нативные |
| COM / UIA | не работают из WSL | работают напрямую |

На 16 ГБ RAM это разница между «впритык» и «свободно». Свой процесс
занимает ~6 ГБ вместе с моделью в VRAM, против 8–10 ГБ у стека в Docker.

### Что придётся построить вместо ODS

| Функция | Чем заменяем |
|---|---|
| llama-server | сайдкар llama.cpp с OpenAI-совместимым HTTP |
| Dashboard | свой UI, раздел «Настройки» |
| Модель-менеджер | свой: скачать, проверить digest, загрузить, откат |
| Qdrant | `sqlite-vec` — встроенная в SQLite, без сервера |
| TEI | локальный эмбеддер (ONNX) в процессе |
| SearXNG | отдельный процесс, либо собственный поиск через HTML-парсер |
| n8n | планировщик на своём тревожном таймере, APScheduler или аналог |
| LiteLLM | слой выбора local/hybrid/cloud в своём коде |
| Token Spy | счётчики в своём UI |
| Portal | полностью наш agent runtime |

Потери честно: это больше работы в Фазе 2, чем взять готовый Portal.
Экономия — в установке, памяти и отсутствии чужого рантайма.

## 4. Аппаратные профили

Профиль определяется автоматически при первом запуске.

| Профиль | RAM | VRAM | Модель | Контекст |
|---|---|---|---|---|
| **T1** базовый | 8 ГБ | встройка / 4 ГБ | Qwen3.5 4B Q4 (~2.5 ГБ) | 16K |
| **T2** средний | 16 ГБ | 8 ГБ | Qwen3.5 9B Q4_K_M (5.06 ГБ) | 32K |
| **T3** комфорт | 32 ГБ | 8 ГБ | Qwen3.5 9B Q5_K_M (~6.5 ГБ) | 64K |
| **T4** продвинутый | 32 ГБ | 12–16 ГБ | Qwen3.5 27B Q4_K_M (~16 ГБ) | 128K |
| **T5** максимум | 64 ГБ+ | 24 ГБ+ | Qwen3.5 27B Q4_K_M + длинный контекст | 262K |

| Профиль | Примеры машин |
|---|---|
| T1 | i5-12400, 8 ГБ, UHD-встройка или 3060 4 ГБ |
| T2 | i5-12400 / Ryzen 5600, 16 ГБ, RTX 3060 8 ГБ |
| T3 | Ryzen 7 8700F, 32 ГБ DDR5, RTX 5060 8 ГБ |
| T4 | Ryzen 7 7800X3D, 32 ГБ, RTX 4070 12 ГБ / 4080 16 ГБ |
| T5 | Ryzen 9 / Core i9, 64 ГБ+, RTX 4090 24 ГБ |

### 4.1 Правило выбора

```
VRAM >= 24 ГБ  → T5
VRAM >= 12 ГБ  → T4
VRAM >= 8 ГБ   → T3, если RAM >= 24 ГБ, иначе T2
VRAM >= 4 ГБ   → T2
VRAM < 4 ГБ    → T1 (CPU-режим)
RAM < 8 ГБ     → не поддерживается
```

| Что | Как |
|---|---|
| VRAM | `nvidia-smi --query-gpu=memory.total` или DXGI |
| RAM | `GlobalMemoryStatusEx` |
| CPU | CPUID, число логических ядер |

Профиль сохраняется, но переопределяется вручную в настройках.
При переопределении пересчитываются: модель, контекст, набор функций.

### 4.2 Бюджеты

**VRAM, профиль T2:**

| Статья | Размер |
|---|---|
| Модель Q4_K_M | 5.06 ГБ |
| Runtime-буферы | ~1.3 ГБ |
| Остаток на KV-кэш | ~1.6 ГБ |

Отсюда: контекст 32K, KV-кэш квантовать в `q8_0`. На 64K не влезает.

**RAM, профиль T2:**

| Потребитель | Размер |
|---|---|
| Windows | 2.5–3.5 ГБ |
| Secretary (UI + агент) | 0.3–0.5 ГБ |
| llama.cpp + эмбеддер | 0.4–0.8 ГБ |
| Whisper + Kokoro | 0.8–1.2 ГБ |
| **Свободно** | **9–11 ГБ** |

Свободного места много. Это позволяет держать в памяти корпус документов
и историю диалогов без выгрузки.

### 4.3 Зрение и VRAM

Полный vision-пайплайн (модель + mmproj + контекст) не помещается в 8 ГБ.

**Решение: управление ПК через UI Automation.**

| Подход | Требует |
|---|---|
| UIA, дерево элементов | ничего, работает по accessibility API |
| Vision по скриншотам | mmproj в VRAM + передача картинок |

UIA отдаёт структурированные данные: заголовки, тексты полей, состояния кнопок.
Для задач «открыть», «ввести», «нажать», «прочитать» этого достаточно, и GPU
не тратится ничего.

На T4–T5 vision доступен и включается по профилю.

### 4.4 Производительность

| Профиль | Ответ в чат | Голосовой цикл | Сценарий (10 шагов) |
|---|---|---|---|
| T1 | 8–20 tok/s | 3–6 сек | 2–5 мин |
| T2 | 20–40 tok/s | 1.5–3 сек | 30–90 сек |
| T3 | 40–70 tok/s | 1–2 сек | 20–50 сек |
| T4 | 30–60 tok/s | <1 сек | 20–60 сек |
| T5 | 30–60 tok/s | <1 сек | 20–60 сек |

T1 ощущается неторопливым. Короткие задачи проходят незаметно, длинные
автономные сценарии на T1 лучше уводить в облако через hybrid.

## 5. Компоненты

### 5.1 Оболочка — Tauri 2

| Вариант | RAM в простое | Выбор |
|---|---|---|
| **Tauri 2** | ~40 МБ | да |
| Electron | ~250 МБ | нет |
| PySide6 | ~120 МБ | запасной |

Tauri использует системный WebView, без рантайма браузера. На T1 это
120 МБ экономии, которые заметны.

| Слой | Выбор |
|---|---|
| Оболочка | Tauri 2 (Rust) |
| Фронт | React + TypeScript + Vite |
| Состояние | TanStack Query |
| IPC | tauri commands |
| HTTP | `reqwest` |

### 5.2 Inference

**llama.cpp как сайдкар.** Не как библиотека — отдельный процесс: его можно
перезапустить и заменить, не трогая основное приложение.

Причины:
- изоляция: падение инференса не роняет UI
- можно обновить отдельно
- можно запускать два экземпляра (основная модель + быстрая)

| Параметр | Значение |
|---|---|
| Tool-call parser | `qwen3_coder` |
| Thinking mode | **выключить** |
| KV-кэш квант | `q8_0` |
| Биндинг | OpenAI-compatible `/v1/chat/completions` |

**Thinking mode обязателен к отключению.** По умолчанию модель генерирует
`<think>...</think>` перед каждым ответом. Для секретаря это лишние секунды.

```json
{"chat_template_kwargs": {"enable_thinking": false}}
```

Сэмплинг для non-thinking режима (из model card):

```
temperature=0.7, top_p=0.8, top_k=20, presence_penalty=1.5
```

### 5.3 Модель-менеджер

Отдельный модуль, по образцу ODS:

1. Определить профиль железа
2. Выбрать модель и квант из каталога
3. Скачать с Hugging Face, проверяя digest каждого файла
4. Проверить: архитектура, размер, требуемые файлы
5. Загрузить в llama.cpp, дождаться готовности
6. Проверить реальным запросом, а не фактом старта процесса
7. Транзакционно: при провале вернуть предыдущую модель

**Bootstrap-режим:** пока большая модель качается, поднимать 4B. Пользователь
может начать работать сразу. Идея из ODS, реализация своя.

Каталог моделей — свой JSON, по структуре как `model-library.json` у ODS:

```json
{
  "t2": {
    "llm": "Qwen/Qwen3.5-9B-GGUF",
    "file": "Qwen3.5-9B-Q4_K_M.gguf",
    "size_gb": 5.06,
    "context": 32768,
    "kv_type": "q8_0",
    "reasoning": false
  }
}
```

### 5.4 Agent runtime

Полностью наш код. Компоненты:

| Компонент | Что делает |
|---|---|
| Tool registry | объявление инструментов с JSON-схемами |
| Tool search | отдавать модели не все схемы сразу, а поиском |
| Executor | цикл: рассуждение → вызов → результат → рассуждение |
| Approvals | проверка уровня автономности, модалка при необходимости |
| Receipts | запись что именно было выполнено и с каким результатом |
| Compaction | ужатие истории при приближении к лимиту контекста |
| Cancellation | отмена текущего шага, возврат статуса |

**Lean tool surface.** При 30+ инструментах полная схема на каждый запрос
съедает контекст. Отдаём модели `tool_search` / `tool_describe` /
`tool_call`, а не все схемы сразу. Идея из ODS, реализация своя.

**Compaction.** Подход из ODS: потолок удерживаемого хвоста, резерв под
вывод, пересчёт бюджета при изменении контекста. Ориентиры:

| Профиль | История | Резерв под вывод |
|---|---|---|
| T1 (16K) | 8K | 4K |
| T2 (32K) | 16K | 8K |
| T3 (64K) | 32K | 16K |
| T4–T5 (128K+) | 64K | 32K |

**Отмена исполнения.** Не флаг в UI, а реальное убийство процесса:
маркер с SHA-256 от идентификатора запуска, убийство process group,
статус 130. Идея из ODS. Без этого «отмена» только обозначает, но не прекращает.

### 5.5 Windows-инструменты

Инструменты живут в процессе приложения и получают нативный доступ.

| Задача | Инструмент | Приоритет |
|---|---|---|
| Файлы: найти, прочитать, создать | `walkdir` + `std::fs` | 1 |
| Запуск приложений | `ShellExecuteW` | 1 |
| Окна: список, заголовки, активация | Win32 `EnumWindows` | 1 |
| Элементы интерфейса | UI Automation (`uiautomation`) | 1 |
| Клик, ввод текста | UIA `Invoke` / `ValuePattern` + SendInput | 1 |
| Интернет: поиск | SearXNG или свой | 1 |
| Интернет: чтение страницы | HTTP + HTML-парсер | 1 |
| Буфер обмена | Win32 clipboard | 2 |
| Уведомления | `toast` / WinRT | 2 |
| Outlook, Excel, Word | COM | 3 |
| Скриншот (по требованию) | `windows::Graphics::Capture` | 3 |

Приоритет 1 — четыре задачи: общение, вопросы, интернет, простые действия
с ПК и файлами. 2 — удобство. 3 — офисные приложения.

**Правило:** инструменты никогда не принимают сырые команды от модели.
Только типизированные аргументы. Это и есть граница безопасности.

### 5.6 Голос

Пайплайн: `wake-word → VAD → STT → LLM → TTS` с прерыванием.

| Компонент | Модель | Зависит от профиля |
|---|---|---|
| Wake-word | openWakeWord (ONNX) | нет |
| VAD | Silero (ONNX) | нет |
| STT | faster-whisper | да |
| TTS | Kokoro-82M | нет |

| Профиль | STT | Цикл |
|---|---|---|
| T1 | `tiny` на CPU | 3–6 сек |
| T2 | `base` | 1.5–3 сек |
| T3+ | `small` на GPU | <1–2 сек |

**Barge-in:** пока TTS говорит, STT продолжает слушать. Распознанная речь
останавливает воспроизведение и начинает новый turn. Проверка эха: сравнение
входящего аудио с синтезированным.

**Fallback:** кнопка «слушать» без wake-word — на случай если детектор
ошибается или микрофон шумит.

### 5.7 Память и RAG

`sqlite-vec` — векторный поиск внутри SQLite. Без отдельного сервера,
без лишней памяти.

| Тип данных | Хранилище |
|---|---|
| Эмбеддинги документов | sqlite-vec, коллекция корпуса |
| Долговременные факты | sqlite-vec, коллекция памяти |
| История диалогов | обычная таблица SQLite |
| Профиль пользователя | JSON |
| Процедуры | таблица с расписанием |

**Эмбеддинги:** BGE-M3 — мультиязычный, 8192 контекст, 1024 измерения.
На ONNX работает в процессе приложения.

**Чанкинг по структуре**, а не фиксированному размеру. Обычно 300–800 токенов
на чанк с перекрытием по границам разделов.

**Бюджет контекста на запрос к документам:**

| Профиль | Top-K | Лимит на чанк |
|---|---|---|
| T1 | 3–5 | 400 токенов |
| T2 | 5–6 | 512 токенов |
| T3+ | 6–8 | 512 токенов |

Больше — не поместится вместе с историей. Это частая причина OOM.

**Запись в память — только явно.** То, что модель решила запомнить:
предпочтения, факты о работе. Не сырой лог диалогов. Иначе база
деградирует за месяцы.

**Индексация — офлайн.** Разбор PDF/DOCX происходит один раз, не в горячем
пути. Изменение файла переиндексирует только его, через `notify`.

### 5.8 Уровни автономности

| Уровень | Что | Пример |
|---|---|---|
| **L1 спрашивает всегда** | Внешние эффекты | отправить письмо, удалить файл |
| **L2 подтверждает** | Изменение состояния | создать файл, закрыть процесс |
| **L3 действует сам** | Только чтение | прочитать документ, найти файл |

Правило: **внешние эффекты всегда с подтверждением.** Ошибка в tool calling
не должна стоить денег или данных.

По умолчанию — консервативные уровни. Пользователь может ослабить.

### 5.9 Облачный fallback

Три режима, как в ODS:

| Режим | Когда |
|---|---|
| local | только локально, приватность абсолютная |
| **hybrid** | локально по умолчанию, облако на сложное |
| cloud | всё в облаке |

Маршрутизация: локально Qwen3.5, облако — на многошаговые задачи, которые
локальная модель тянет плохо. Пользователь видит, когда запрос ушёл наружу.

По умолчанию — local. Облако включается явно.

## 6. Установка

### 6.1 Что ставится

| Компонент | Формат |
|---|---|
| Приложение | один `.exe` + `llama-server.exe` |
| Модель | скачивается при первом запуске, 2.5–16 ГБ |
| Сетар для распознавания | скачивается вместе с моделью |

Ничего доустанавливать не нужно. Нет WSL2, нет Docker, нет перезагрузки.

### 6.2 Первый запуск

1. Приложение определяет профиль железа
2. Показывает профиль и модель, спросит подтверждение
3. Скачивает модель (5–16 ГБ), показывает прогресс
4. Поднимает 4B как bootstrap, если модель большая
5. Проверяет модель реальным запросом
6. Готов к работе

### 6.3 Конфигурация

Профиль определяется автоматически. Ручные настройки:

```json
{
  "profile": "auto",
  "context": 32768,
  "kv_cache_type": "q8_0",
  "thinking_mode": false,
  "cloud_mode": "local",
  "autonomy": { "L1": "always_ask", "L2": "confirm", "L3": "allow" }
}
```

## 7. Распространение

### 7.1 Установка в один шаг

Один `.exe`, всё внутри. Пользователь не должен открывать терминал.

| Требование | Почему |
|---|---|
| Один установщик | массовый пользователь не читает README |
| Проверка предусловий до изменений | не оставлять систему сломанной |
| Откат при неудаче | установка должна быть обратимой |
| Понятные сообщения | «не удалось загрузить модель», не стектрейс |
| Без прав администратора | где возможно |

### 7.2 Настройки пользователя

| Что | Где | Синхронизация |
|---|---|---|
| Профиль железа | определяется, переопределяется вручную | нет |
| Профиль голоса | настройки UI | да |
| Уровни автономности | консервативные по умолчанию | да |
| Корпус документов | локальный путь | нет |
| Память фактов | локально | по выбору |
| Ключ облака | локально, DPAPI | нет |
| История диалогов | локально | по выбору |

Приватность по умолчанию: всё локально, синхронизация выключена,
облако выключено.

### 7.3 Диагностика

Пользователь не должен гадать. Кнопка «Диагностика» выдаёт конкретное действие:

| Симптом | Причина | Что показать |
|---|---|---|
| «Не отвечает» | модель не загрузилась | «Перезагрузить модель» |
| «Всё медленно» | модель не в VRAM | «Переключить на Q4_K_S» |
| «Не понимает по-русски» | модель | «Попробовать Gemma 4» |
| «Не видит документы» | индекс не создан | «Выбрать папку и проиндексировать» |
| «Мало VRAM» | mmproj + модель | «Отключить vision» |
| «Не слышит» | микрофон или wake-word | «Проверить микрофон», «Выключить wake-word» |

### 7.4 Обновления

| Что | Как | Риск |
|---|---|---|
| Приложение | автообновление | низкий |
| llama.cpp | замена бинаря | средний, нужен регресс-тест |
| Модель | смена кванта из каталога | низкий |

Смена кванта не должна ломать профиль: это подбор из уже загруженных
вариантов, без смены архитектуры.

### 7.5 Адаптация функций по профилю

| Функция | T1 | T2 | T3 | T4–T5 |
|---|---|---|---|---|
| Текстовый чат | да | да | да | да |
| Голос | база | база | small STT | small + быстрый отклик |
| Управление ПК (UIA) | простые окна | да | да | да + vision |
| Интернет | да | да | да | да |
| RAG по документам | ограниченно | да | да | больше Top-K |
| Долговременная память | нет | ограниченно | да | да |
| Напоминания | нет | да | да | да |
| Контекст диалога | 16K | 32K | 64K | 128K+ |

**Правило: функция либо работает полностью, либо не показывается вовсе.**
Половина функции хуже, чем её отсутствие — пользователь не поймёт, что сломалось.

## 8. Модели

| Профиль | Модель | Размер | Примечание |
|---|---|---|---|
| T1 | Qwen3.5 4B Q4 | ~2.5 ГБ | единственное, что влезает на 8 ГБ RAM |
| T2 | Qwen3.5 9B Q4_K_M | 5.06 ГБ | базовая, KV-кэш q8_0 |
| T2 запас | Qwen3.5 9B Q4_K_S | 4.09 ГБ | если RAM упирается |
| T3 | Qwen3.5 9B Q5_K_M | ~6.5 ГБ | выше точность |
| T4 | Qwen3.5 27B Q4_K_M | ~16 ГБ | помещается в 12–16 ГБ с контекстом |
| T5 | Qwen3.5 27B Q4_K_M | ~16 ГБ | 262K контекст |
| Замена | Gemma 4 12B QAT | ~7.5 ГБ | если на русском Qwen хуже |
| Альт | Bonsai 27B ternary | 7.2 ГБ | требует форк llama.cpp, не рекомендуется |

**Про Bonsai:** требует кастомных Q2_0_g128 ядер форка PrismML. В нашем
собственном рантайме это меньшая проблема, чем была в ODS — можно собрать
сайдкар из форка. Но на 24 ГБ VRAM Qwen3.5 27B Q4_K_M даёт лучшее
соотношение качества и простоты. Bonsai оставлен как альтернатива.

Источники GGUF: `bartowski/Qwen_Qwen3.5-9B-GGUF`, `unsloth/Qwen3.5-9B-GGUF`.

## 9. Идеи из ODS

Что стоит перенести в наш код — проверенные решения, а не готовые модули.

| Идея | Зачем |
|---|---|
| Каталог моделей с детерминированным выбором | воспроизводимость: одно железо → один выбор |
| Bootstrap: маленькая модель сразу, большая в фоне | не ждать 10 минут до первого ответа |
| Транзакционная смена модели | при провале откат, а не сломанный стенд |
| Lean tool surface через поиск | 30+ инструментов не влезают в контекст |
| Компакция с пересчётом бюджета | история не должна съедать окно |
| Отмена как убийство process group | «отмена» должна прекращать, а не обозначать |
| Карантин загрузок с проверкой digest | файл публикуется только после проверки |
| Fail closed при любом расхождении | неясность лучше опасного действия |
| Уровни автономности L1/L2/L3 | внешние эффекты всегда подтверждаются |
| Модель не форматирует команды вручную | типизированные схемы вместо сырых строк |
